## خريطة ملكية الموضوعات لاستكمال التحرير

القوائم التالية حدود دروس مقترحة للعمل المتبقي، وليست دروسًا منشورة أو علامة اكتمال. قبل أي تقسيم: اقرأ الملف الأصلي كاملًا، انقل كل معلومة صحيحة إلى موضوعها، حدّث روابط اللغتين، ثم اختبر الأمثلة. لا تنفذ الفصل آليًا بمجرد وجود عنوان H2.

### الأساسيات

- مقدمة الجهاز: CPU وRAM والتخزين ومسار بيانات مختصر. تفاصيل شراء القطع واللوحة والتوصيلات المتخصصة ليست مدخل البرمجة.
- السوفتوير: المصدر والبرنامج والعملية وRuntime والمكتبات وFrameworks، مع مثال تشغيل واحد يفسر الفرق.
- نظام التشغيل: Kernel وUser/Kernel Mode وSystem Calls ثم عمليات وجدولة وموارد وصلاحيات، من خلال تنفيذ وملف فعليين.
- CPU: التعليمات والتتابع والـcache وتأثير نوع الحمل؛ GPU: نوع العمل المتوازي وحدود ملاءمته، وليس تعداد مواصفات.
- تمثيل البيانات: البت والبايت والأعداد والإشارة والمدى والترميز. الصور والصوت والفيديو درس تطبيقي واضح يعتمد عليها.
- الذاكرة الافتراضية: العناوين والصفحات والحماية وpage fault وswap. إدارة عمر البيانات درس متميز عن العناوين.
- الملفات: فتح/قراءة/كتابة/إغلاق، buffering وflush وضمانات الحفظ والـatomic replace وحدود كل منها.
- العمليات والتزامن: الانتظار مقابل العمل، تزامن/توازٍ، IPC وحماية البيانات المشتركة.
- أدوات التنفيذ: Terminal/Shell وPATH وقنوات stdin/stdout/stderr وكود الخروج والصلاحيات، بأمثلة PHP.

### الشبكات

- كل بروتوكول رئيسي له درس مالك: IP، TCP، UDP، DNS، HTTP، TLS.
- TCP يجمع المصافحة والنقل والنوافذ والفقد والإغلاق والمهلات وتشخيص الاتصال، مع مقارنة محدودة لا تستبدل درس UDP.
- DNS يجمع بنية الاسم وresolver وauthoritative/cache/TTL ومسار الإجابة والأخطاء والأمان المناسب للمستوى.
- TLS يجمع الثقة والشهادات والتحقق من الاسم والـhandshake ومفاتيح الجلسة وحدود الحماية والفشل.
- HTTP يجمع بنية الطلب والرد وmethods/status/headers/body والـmessage framing قبل تفاصيل الإصدارات.
- فصل موضوعات طبقة التطبيق ذات الغرض المختلف: cookies/session، caching، CORS، reverse proxy، load balancing، CDN، webhooks، SSE/WebSocket، observability.
- لا توحّد كل الشبكات في درس واحد ضخم؛ الاستقلال حول موضوع له بداية ونهاية، مع متطلبات محددة.
- المقارنة مع PDF الأصلي معلقة على توفير الأصل، لا على الذاكرة.

### PHP

- البداية والـCLI والوسوم والصياغة والمخرجات؛ مثال كامل مع command ونتيجة.
- المتغيرات والإسناد والتسمية، ثم الأنواع والتحويل والمقارنة كموضوع له أمثلته وحدوده.
- Scope مرتبط بالدوال وclosures ومتطلبات واضحة؛ Superglobals مرتبط بطلب HTTP ومصادر المدخلات، لا مقدمة المتغيرات.
- if/else، switch، match موضوعات مترابطة لكن لكل منها بناء واضح؛ الحلقات موضوع يضم أنماطها ومتى تتوقف.
- Functions: parameters/returns/types/default/named/variadic وبناء stack بسيط.
- Arrays: المفاتيح والأنواع والترتيب والعمليات والتحويل والذاكرة. Strings: bytes/Unicode/encoding والتقسيم والبحث. Regex موضوع مستقل لو زاد حجمه.
- Files وStreams، ثم JSON/serialization مع الحدود والأخطاء.
- Exceptions والأخطاء؛ Namespaces/Autoloading مع مشروع Composer صغير.
- HTTP request/response، ثم uploads، cookies، sessions كموضوعات مستقلة بأمثلة تصلح للمختبر.
- لا تضع generators وFibers وWeakMap وenums في درس واحد بعنوان «ميزات حديثة». كل ميزة في سياق حاجتها مع متطلباتها.

### PHP Runtime

- PHP CLI وSAPI وphp.ini والامتدادات قبل إعدادات FPM المتقدمة.
- Composer وإدارة الحزم؛ Autoloading وتحسينه مرتبطان به لكن بشرح آلية تحميل الاسم لا وصفة أوامر فقط.
- OPcache درس له invalidation وتوافق النشر؛ Preloading إن احتاج درسًا مستقلاً يعلن متطلباته بوضوح.
- إدارة ذاكرة PHP: zval/refcount/copy-on-write/GC من سلوك كود قابل للقياس.
- خادم الويب، FastCGI، PHP-FPM لكل منه دوره؛ تجمعهم صفحة خريطة وليست بديلًا عن دروسهم.
- متغيرات البيئة والإعدادات والأسرار؛ HTTP client ومهلاته وإعادة المحاولة.
- Logging، Metrics، Tracing وProfiling موضوعات منفصلة، لا فقرة تعريف لكل أداة.
- Cache، Queue، Worker، Scheduler وlong-running runtimes لها حدود مسؤولية وتمارين فشل.
- Testing، Deployment، CI/CD، Containers، Backup/Recovery تتدرج بعد متطلبات التنفيذ والشبكات.

### Database

- البيانات والجدول والصف والعمود ثم types وNULL؛ المفاتيح والعلاقات والقيود مع schema قابلة للتشغيل.
- SQL قراءة وفلترة وتجميع وربط وتعديل؛ لا تختبئ خلف ORM قبل فهم الـquery.
- PDO: الاتصال والأخطاء وprepared statements والقيم مقابل identifiers والقراءة والذاكرة.
- Transactions: atomicity وحدود الوحدة وcommit/rollback مع مثال نجاح وفشل.
- Isolation: قراءتان متزامنتان أو أكثر توضحان المشكلة؛ locks وdeadlocks والسياسة المطلوبة بدل تعريفات مجردة.
- Indexes: access pattern ثم بنية وفهرس ومقارنة plan؛ EXPLAIN وPagination يلزمان أمثلة بيانات ونتائج واضحة.
- Migrations: التغيير والتوافق والـbackfill وexpand/contract والإصلاح؛ لا تقللها إلى اسم ملف وتاريخ.
- ORM: Model/Builder/Collection وSQL الفعلي وعدد queries، مع Active Record/Data Mapper ومقارنة التكاليف.

### Authentication / Security

- Identity ثم Authentication وAuthorization قبل درس تفاصيل Session؛ مسار الدخول وتحقق الملكية واضحان.
- Password hashing، sessions/cookies، CSRF، XSS، input validation كل منها يشرح أصل التهديد قبل الدفاع.
- Encryption درس، HTTP Basic/Bearer درس؛ لا تخلط التشفير والتوقيع والترميز والـhash.
- JWT: البنية والتوقيع والتحقق والأخطاء والـclaims والمفاتيح، مع رفض tokens غير صالحة فعليًا.
- OAuth: نموذج واحد كامل متدرج، وتفاصيل flows المختلفة داخل أقسام تفسر الأطراف والرسائل والأخطاء؛ OIDC هوية فوق تفويض OAuth ويحتاج شرحًا مستقلاً.
- SAML له نموذج ورسائل وثقة مختلفة؛ SSO نتيجة استخدام وليس اسم بروتوكول بديل.
- MFA/TOTP وPasskeys/WebAuthn موضوعات مستقلة بحدود recovery وstep-up.
- API keys، HMAC/webhooks، service identity، tenant isolation، rate limits، audit logs، secrets، incident response كل موضوع له سيناريو اختبار سلبي يناسبه.
