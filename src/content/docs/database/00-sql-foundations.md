قبل ما نتعلم PDO أو ORM، محتاجين نفهم السؤال اللي بنوجهه لقاعدة البيانات. في الدرس ده هنبني جدول طلاب ومحاولات، ونستخرج عدد المحاولات ومتوسط درجات كل طالب، حتى الطالب اللي ماحاولش.

## من البيانات إلى جدولين

الجدول مجموعة صفوف لها أعمدة محددة. الصف هنا طالب واحد أو محاولة واحدة. المفتاح الأساسي `PRIMARY KEY` بيميز كل صف؛ الاسم وحده مش كفاية لأن طالبين ممكن يكون لهم نفس الاسم. المفتاح الخارجي `FOREIGN KEY` بيربط محاولة بطالب موجود. العلاقة هنا واحد إلى متعدد: الطالب له محاولات كثيرة، والمحاولة تخص طالبًا واحدًا.

`NOT NULL` يمنع غياب قيمة لازمة، و`CHECK` يفرض قاعدة زي درجة بين صفر و100. التحقق في PHP يعطي رسالة مفهومة، والقيود في قاعدة البيانات تحمي القاعدة حتى لو برنامج آخر كتب فيها.

## اكتب السؤال قبل SQL

عايزين كل الطلاب، ونضم محاولاتهم، ثم نلخص كل مجموعة محاولات. `SELECT` يحدد الأعمدة الناتجة، و`FROM` الجدول الذي نبدأ منه. `LEFT JOIN` يحافظ على طالب بلا محاولات؛ `INNER JOIN` هيستبعده. شرط `ON` يحدد أي محاولة تخص أي طالب، و`AS` يعطي اسمًا مختصرًا للجدول أو اسمًا واضحًا للعمود الناتج.

```sql
CREATE TABLE learners (id INTEGER PRIMARY KEY, name TEXT NOT NULL);
CREATE TABLE attempts (
    id INTEGER PRIMARY KEY,
    learner_id INTEGER NOT NULL REFERENCES learners(id),
    score INTEGER NOT NULL CHECK(score BETWEEN 0 AND 100)
);
INSERT INTO learners VALUES (1, 'Omar'), (2, 'Mona'), (3, 'Ali');
INSERT INTO attempts VALUES (1, 1, 80), (2, 1, 100), (3, 2, 60);
SELECT l.id, l.name, COUNT(a.id) AS attempts, AVG(a.score) AS average
FROM learners AS l
LEFT JOIN attempts AS a ON a.learner_id = l.id
GROUP BY l.id, l.name
ORDER BY l.id;
```

نفّذ المثال الكامل الجاهز بالأمر `php sql-foundations.php` من [المختبر](/php/00-lab-setup/). الملف ينشئ قاعدة SQLite مؤقتة في الذاكرة ويفعّل قيود العلاقات، ثم ينفذ نفس SQL ويطبع JSON. كائن PDO هو اتصال PHP بقاعدة البيانات؛ الدرس التالي هيفكك الاتصال والاستعلام المحضّر خطوة خطوة.

| الطالب | عدد المحاولات | المتوسط |
|---|---:|---:|
| Omar | 2 | 90 |
| Mona | 1 | 60 |
| Ali | 0 | NULL |

`GROUP BY` يجمع صفوف الطالب قبل `COUNT` و`AVG`. استخدمنا `COUNT(a.id)` علشان الصف الناتج من LEFT JOIN بلا محاولة مايتحسبش كمحاولة؛ `COUNT(*)` كان هيحسب صف Ali ويطلع 1. `AVG` يتجاهل NULL، ولعدم وجود درجات يرجع NULL، مش صفرًا. `ORDER BY` يضمن ترتيبًا محددًا؛ ترتيب الإدخال مش ضمان لترتيب النتيجة.

## الفلترة والتعديل

`WHERE` يفلتر الصفوف قبل التجميع، و`HAVING` يفلتر المجموعات بعده. لإظهار متوسط أعلى من 70 أضف `HAVING AVG(a.score) > 70` بعد GROUP BY وقبل ORDER BY: النتيجة Omar فقط. لو نقلت شرطًا على جدول المحاولات إلى WHERE بعد LEFT JOIN، ممكن تستبعد الطالب بلا محاولات من غير قصد.

`NULL` معناها قيمة مجهولة أو غير موجودة؛ افحصها بـ`IS NULL`، مش `= NULL`. المقارنة مع NULL لا تنتج true، وWHERE يحتفظ فقط بالصفوف اللي شرطها true.

```sql
UPDATE attempts SET score = 85 WHERE id = 1;
DELETE FROM attempts WHERE id = 3;
```

دول مثالان للتنفيذ بعد الإنشاء: الأول يعدّل محاولة واحدة والثاني يحذف واحدة. قبل تعديل مهم، جرّب SELECT بنفس WHERE وراجع الصفوف، واستخدم معاملة عندما تتعاون تغييرات متعددة. نسيان WHERE قد يغير كل الصفوف. في التطبيق مرّر القيم عبر placeholders، ولا تلصق مدخل المستخدم في SQL.

## الفهرس مش قاعدة صحة

الفهرس بنية إضافية تساعد المحرك يلاقي الصفوف أسرع، لكنه يستهلك مساحة ويزيد كلفة الكتابة. فهرس على `attempts(learner_id)` قد يساعد الربط. الفهرس العادي لا يمنع التكرار؛ `UNIQUE` يفرض عدم تكرار القيم حسب سلوك المحرك. استخدم خطة التنفيذ وبيانات واقعية قبل الحكم على الأداء.

## جرّب وفسر

أضف طالبًا رابعًا بلا محاولات: المفروض يظهر بعداد صفر ومتوسط NULL. حاول إدخال درجة 101 أو `learner_id=999`: القيود ترفض الحالتين. غيّر LEFT JOIN إلى INNER JOIN: يختفي Ali. الحل مش حفظ الأوامر، بل تتبع الصفوف قبل الربط وبعده وبعد التجميع.

SQLite هنا وسيلة تشغيل سهلة. أنواع الأعمدة، تفعيل العلاقات، أوامر الهوية، الأقفال ومستويات العزل تختلف بين المحركات؛ ارجع لدروس PDO والمعاملات قبل نقل المثال إلى MySQL أو PostgreSQL.
