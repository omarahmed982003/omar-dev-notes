ذاكر الدرس على 3 خطوات: افهم المشكلة الأول، تابع المثال، وبعدها جرّب الجزء العملي بنفسك. المصطلحات الجديدة الموجودة تحت متشرحة قبل ما ندخل في التفاصيل.

- **Loop:** حلقة تكرار تعيد تنفيذ مجموعة تعليمات وفق شرط.


## تحليل المشكلة قبل كتابة الكود

قبل كتابة C++ ثبّت منطق الحل: حدّد المدخلات والنتيجة، اكتب الخطوات، مثّل القرارات، ثم اختبر الخوارزمية يدويًا. اللغة تنفذ التفكير ولا تستبدله.

## Pseudocode وFlowchart وجدول التتبّع

الـ`Pseudocode` وصف منظم للحل بلغة قريبة من الإنسان. نستخدم فيه كلمات مثل `READ` و`IF` و`REPEAT` من غير التقيد بقواعد C++. فائدته أن منطق الحل يصبح قابلًا للمراجعة قبل أن تدخل تفاصيل الأقواس والأنواع والمكتبات.

الـ`Flowchart` يمثل الخطوات بأشكال وأسهم. المستطيل يعني عملية، والمعيّن يعني قرارًا له مساران أو أكثر، ومتوازي الأضلاع يمثل إدخالًا أو إخراجًا. يجب أن يقود كل سهم إلى خطوة محددة وألا يوجد مسار ينتهي بلا نتيجة واضحة.

جدول التتبّع يسجل قيم المتغيرات بعد كل خطوة. إذا كان البرنامج يحسب مجموعًا، فاكتب قيمة العداد والمجموع بعد كل دورة. ستعرف عندها هل الخطأ بدأ من التهيئة أم من الشرط أم من التحديث.

ابدأ بحالة عادية صحيحة، ثم اختبر القيم عند الحدود والمدخلات غير الصالحة. الخطأ النحوي يمنع المترجم من بناء البرنامج، وخطأ وقت التشغيل يظهر أثناء التنفيذ، أما الخطأ المنطقي فينتج قيمة خاطئة رغم أن البرنامج يعمل.

## مثال: القسمة مع فحص المقام

```text
READ a, b
IF b = 0 THEN
  PRINT "Division is undefined"
ELSE
  PRINT a / b
END IF
```

## أشجار القرار وقواعد العمل

شجرة القرار تعرض سؤالًا عند كل عقدة، وفرعًا لكل إجابة ممكنة، ونتيجة نهائية عند كل Leaf. تفيد عندما تعتمد النتيجة على شروط مترابطة أو متداخلة، وتكشف المسارات الناقصة والقواعد المتعارضة قبل كتابة `if`.

في مثال الموافقة على قرض يمكن أن يبدأ القرار بالعمر، ثم الدخل، ثم الضامن أو Credit score. لا يكفي رسم المسار الناجح؛ يجب أن ينتهي كل مسار إلى موافقة أو رفض أو مراجعة يدوية. حوّل الشجرة بعد ذلك إلى شروط مرتبة، مع اختبار حالة الحد مثل عمر 21 بالضبط.

## Flowchart وPseudocode

يشرح Flowchart سير العمل بصريًا، بينما يصف Pseudocode الخطوات بنص منظم مستقل عن اللغة. استخدم الشكل البيضاوي للبداية والنهاية، والمستطيل للعملية، والمعين للقرار، ومتوازي الأضلاع للإدخال والإخراج، والأسهم لاتجاه التنفيذ. Connector يربط أجزاء الرسم دون خطوط متقاطعة طويلة.

```text
INPUT number
IF number > 0
    OUTPUT "Positive"
ELSE IF number < 0
    OUTPUT "Negative"
ELSE
    OUTPUT "Zero"
END IF
```

عند رسم حاسبة بسيطة، تتفرع العملية حسب العامل، ثم يفحص فرع القسمة المقام قبل الحساب. تعود الفروع الناجحة إلى نقطة إخراج واحدة، بينما يسلك العامل غير المدعوم مسار خطأ واضحًا.

## Test cases قبل الكود

أنشئ حالات عادية، وحدّية، وغير صالحة. قاعدة خصم تبدأ من 500 تحتاج 499 و500 و501. إذا كان الشرط مكتوبًا `subtotal > 500` فستكشف حالة 500 الخطأ فورًا. ويساعد جدول القرار عندما توجد عدة شروط، لأنه يسجل كل Combination والنتيجة المقابلة.

## تتبع الخطأ المنطقي

الـLogic error يسمح للبرنامج بالعمل لكنه ينتج قيمة خاطئة أو لا ينتهي. ابحث عن أول حالة تختلف فيها القيمة الفعلية عن المتوقعة:

1. أعد الخطأ بمدخل ثابت.
2. تتبع المسار خطوة بخطوة.
3. سجل قيم المتغيرات بعد كل خطوة أو Iteration.
4. أصلح أول سبب، لا النتائج التابعة له.
5. أعد الحالة الفاشلة والحالات المجاورة.

في مجموع Running total إذا كان المتوقع بعد المدخلين `5` و`3` هو `8` لكن الفعلي `10`، فابدأ بالـIteration الثانية. الخطأ في الـIteration الثالثة قد يكون مجرد أثر للقيمة السابقة.

## تعريف المشكلة والمدخلات والمخرجات والقيود

المشكلة البرمجية عقد يحدد ما يدخل إلى البرنامج وما يجب أن يخرج منه. اكتب المدخلات بأسمائها وأنواعها ووحداتها. `price` وحده غامض؛ هل هو بالجنيه أم بالقرش؟ وهل يقبل كسرًا؟ وهل يمكن أن يكون صفرًا؟ واكتب المخرجات بنفس الدقة: هل المطلوب المجموع فقط أم فاتورة تفصيلية ورسالة خطأ عند فشل الإدخال؟

القيود تحدد الحل الممكن. إذا كان عدد العناصر عشرة، فقد يعمل حل يقارن كل عنصر بالآخر. إذا وصل العدد إلى مليون، قد يصبح الحل نفسه بطيئًا جدًا. وتشمل القيود قواعد المجال، مثل أن العمر بين 12 و80، والكمية موجبة، والمقام لا يساوي صفرًا.

اكتب الافتراضات التي لم يحددها السؤال. إذا كان السعر سالبًا، هل ترفضه أم تعتبره مرتجعًا؟ إذا تساوى متسابقان، هل توجد نتيجة تعادل؟ تحويل الغموض إلى قرار مكتوب يمنع ظهور سلوك مختلف في كل جزء من البرنامج.

## الخوارزمية وصحة الخطوات

الخوارزمية سلسلة خطوات محدودة وغير غامضة تحول المدخلات إلى المخرجات. «محدودة» تعني أن التنفيذ يصل إلى نهاية، ولذلك يجب أن تتغير حالة أي تكرار باتجاه التوقف. و«غير غامضة» تعني أن كل خطوة قابلة للتنفيذ، فلا نكتب «احسب الحل المناسب» من غير تعريف طريقة الحساب.

نختبر صحة الخوارزمية بسؤالين: هل تعطي النتيجة الصحيحة لكل مدخل صالح؟ وهل تتوقف؟ تتبع مثال يدوي مفيد، لكنه لا يثبت الصحة وحده. قسّم مجال المدخلات إلى فئات، واختر حالة من كل فئة، ثم اختبر الحدود التي تتغير عندها القرارات.

## رموز الـFlowchart

| الشكل | معناه | مثال |
|---|---|---|
| بيضاوي | بداية أو نهاية | Start، End |
| متوازي أضلاع | إدخال أو إخراج | Read age، Print total |
| مستطيل | عملية حسابية أو إسناد | `total = price * quantity` |
| معيّن | قرار | `quantity > 0?` |
| سهم | اتجاه التنفيذ | الانتقال من الفحص إلى الحساب |

يجب أن يحمل كل فرع خارج من المعيّن معنى مثل نعم/لا، وأن يعود مسار التكرار إلى القرار الصحيح. إذا ازدحم الرسم، قسّم العمل إلى خوارزميات فرعية بدل تقاطع الأسهم بلا دلالة.

## حالات الاختبار المتكافئة والحدود

لا تحتاج إلى اختبار كل رقم ممكن. قسّم القيم إلى مجموعات تتعامل معها الخوارزمية بالطريقة نفسها. لشرط `score >= 60` توجد فئة أقل من 60 وفئة من 60 فأكثر، بالإضافة إلى القيم غير الصالحة خارج `0..100`. اختبر `59` و`60` و`61` لكشف أخطاء الحد، ثم `-1` و`101` لاختبار التحقق.

اكتب لكل اختبار المدخلات والنتيجة المتوقعة وسبب اختيار الحالة. إذا ظهر خطأ، احتفظ بالاختبار بعد إصلاحه حتى لا يعود لاحقًا. يسمى ذلك Regression Test لأنه يحمي سلوكًا سبق أن تعطل.


## طبّق طريقة حل المشكلة على منصات التدريب

## ما البرمجة التنافسية؟

البرمجة التنافسية تدريب مركز على تحليل القيود واختيار الخوارزمية وكتابة حل صحيح سريع. المنصة أداة قياس وليست بديلًا عن الفهم.

## قراءة المسألة والقيود والتعقيد

المسألة التنافسية تحدد صيغة الإدخال والنتيجة المطلوبة والقيود. اقرأ هذه الأجزاء قبل الأمثلة لأن المثال يوضح حالة واحدة، بينما القيود تحدد ما إذا كان الحل ممكنًا. إذا كان `n` يصل إلى `100000`، فإن مقارنة كل عنصر بكل عنصر قد تنفذ نحو عشرة مليارات عملية، ولذلك يكون `O(n²)` غير مناسب غالبًا.

حل مثالًا صغيرًا يدويًا واكتب العلاقة الرياضية أو حالة التكرار قبل الكود. اختر النوع من أكبر نتيجة وسيطة، لا من شكل العينة. بعد الانتهاء اكتب تعقيد الزمن والذاكرة حتى تتأكد أن الحل يناسب الحدود.

نتيجة `Wrong Answer` تعني أن البرنامج أنهى التنفيذ لكنه أعاد نتيجة مختلفة. راجع فهم النص والحدود ومواضع `1-based` و`0-based` ونوع البيانات والتقريب. `Runtime Error` يشير غالبًا إلى وصول غير صالح أو قسمة على صفر، و`Time Limit Exceeded` يعني أن عدد العمليات أكبر من المسموح. تغيير الأسطر عشوائيًا لا يشخص السبب.

## مثال: مسألة Elephant والقسمة السقفية

```cpp
// Elephant: minimum moves of length at most 5
int moves = (distance + 4) / 5; // integer ceiling
```

### برنامج كامل قابل للتشغيل

```cpp
#include <iostream>

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    int distance{};
    if (!(std::cin >> distance) || distance < 0) {
        return 1;
    }

    const int moves = (distance + 4) / 5;
    std::cout << moves << '\n';
}
```

إذا كان الإدخال `12` فالخروج `3`: خطوتان بطول 5 وخطوة أخيرة بطول 2. الزمن `O(1)` والذاكرة `O(1)`. لا يطبع البرنامج رسالة مثل `Enter distance` لأن الـOnline Judge يقارن الخرج حرفيًا. فحص الإدخال هنا مفيد عند تشغيل المثال محليًا، بينما تضمن المسألة الأصلية عادة أن الإدخال يطابق القيود.

## دورة عمل الـOnline Judge

يرسل المتسابق Source Code، فتترجمه المنصة بإصدار وخيارات محددة ثم تشغله على حالات مخفية داخل حدود للوقت والذاكرة. تقارن المنصة الخرج المتوقع بالفعلي وفق Checker. أي نص إضافي مثل `Enter n:` قد يسبب Wrong Answer لأن المطلوب تنسيق دقيق.

## تصنيف النتائج

`Compilation Error` يعني أن المصدر لم يُبنَ. `Wrong Answer` يعني أن التنفيذ انتهى لكن الخرج خاطئ. `Runtime Error` يشمل الانهيار والقسمة على صفر والوصول غير الصالح. `Time Limit Exceeded` يدل على زمن زائد، و`Memory Limit Exceeded` على استهلاك ذاكرة أكبر من الحد.

بعد القبول، لا تكتف بالكود. سجل الفكرة والتعقيد والحالة التي أخطأت فيها، ثم أعد الحل بعد أيام من الذاكرة. الهدف بناء نمط تفكير يمكن نقله إلى مسألة جديدة.

## اربط النقاط ببعض

بعد رسم الحل، اكتب loop invariant أو شرطًا يبقى صحيحًا عند كل خطوة، وحدد termination بدل الاكتفاء بأن الأمثلة تعمل. حوّل مثال القسمة إلى برنامج C++ كامل باختبارات للصفر والقيم السالبة والحدود، وقارن trace بالتوقع.

### جرّب بنفسك
