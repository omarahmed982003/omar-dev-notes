## تعليمتان ثم مكان البيانات

افترض تعليمتين مبسطتين: ضع 5 في مكان عمل داخل المعالج، ثم أضف 3 إلى نفس القيمة. المكان الصغير داخل المعالج اسمه **Register — سجل**. المعالج يجلب التعليمة، يفهم العملية المطلوبة، ثم ينفذها؛ الناتج بعد الأولى 5 وبعد الثانية 8. دي صورة تعليمية، مش صياغة لغة آلة بعينها.

```text
CPU registers ↔ L1 cache ↔ L2 cache ↔ L3 cache ↔ RAM
```

**Cache — ذاكرة تحتفظ بنسخة قريبة** تقلل انتظار البيانات المتكررة. L1 وL2 وL3 مستويات؛ هذا ترتيب شائع مبسط، وقد يختلف التنظيم والمشاركة بين الأنوية. السهم يعني طلب بيانات أو نقلها، وليس ضرورة مرور كل قراءة بكل مستوى. بعد ثبات الصورة نضيف تفاصيل التوازي والتنبؤ.

## داخل CPU

ينفذ المعالج دورة Fetch–Decode–Execute. Program Counter (سجل يحدد موضع التعليمة التالية حسب تنفيذ المعالج) يحدد التعليمة التالية، Control Unit (وحدة تنظم فك التعليمات وتنسيق تنفيذها) تفكها وتنسق التنفيذ، ALU (Arithmetic Logic Unit؛ وحدة الحساب والمنطق داخل المعالج) تنفذ الحساب والمنطق، Registers (سجلات: أماكن صغيرة وسريعة جدًا لحمل قيم قريبة من التنفيذ) تحمل القيم الأقرب للتنفيذ، ووحدات أخرى تعالج Floating Point وVectors وBranches وMemory Access.

المعالجات الحديثة تنفذ عدة تعليمات في مراحل متداخلة وتستخدم Branch Prediction (توقع الفرع التالي لتجهيز تعليماته قبل معرفة نتيجة الشرط) وOut-of-order Execution (تنفيذ تعليمات جاهزة بترتيب داخلي مختلف مع الحفاظ على النتائج المطلوبة). لذلك “تعليمة واحدة كل Clock (إيقاع دورات المعالج؛ لا يساوي عدد التعليمات)” تبسيط، والأداء لا يقاس بالـGHz (جيجاهرتز؛ مليار دورة في الثانية، وليس عدد تعليمات منجزة) وحده.

## Cores وThreads وClock وIPC

Core (نواة معالجة تملك موارد تنفيذ فعلية) يستطيع تنفيذ Stream تعليمات مستقلًا. Hardware Thread (سياق تنفيذ عتادي يشارك موارد النواة وقد لا يملك نواة كاملة مستقلة) يسمح بمشاركة بعض موارد Core لتحسين الاستفادة، لكنه ليس Core كاملًا. Clock يحدد عدد الدورات، وIPC (Instructions Per Cycle؛ متوسط عدد التعليمات المنجزة في دورة للمعالج) يصف مقدار العمل المنجز في الدورة. الأداء يعتمد على الاثنين إضافة إلى الذاكرة والكود والحرارة وحدود الطاقة.

زيادة الأنوية تفيد فقط عندما يمكن تقسيم العمل. جزء Serial أوLock (قفل ينظم الوصول المشترك حتى لا تتداخل عمليات متعارضة) مشترك قد يحد التسارع وفق Amdahl's Law (قانون يبين كيف يحد الجزء الذي لا يمكن تقسيمه من تسريع البرنامج كله).

## Registers وL1/L2/L3 Cache

Registers أصغر وأسرع تخزين داخل Core. L1 صغيرة وسريعة جدًا، L2 أكبر وأبطأ، وL3 أكبر وغالبًا مشتركة. Cache (نسخة محفوظة لتقليل تكرار القراءة أو الحساب) تنقل البيانات في Cache Lines (كتل تنقلها ذاكرة المعالج المؤقتة بدل بايت منفرد كل مرة)؛ الوصول المتجاور يستفيد من Locality (استخدام بيانات قريبة مكانيًا أو إعادة استخدامها قريبًا زمنيًا)، بينما القفز العشوائي يسبب Cache Misses (مرات عدم وجود البيانات المطلوبة في المستوى المفحوص من الذاكرة المؤقتة) وانتظار RAM (Random Access Memory؛ ذاكرة العمل التي تحمل بيانات وتعليمات البرامج النشطة).

Cache ليست RAM إضافية يديرها البرنامج عادة، ولا تضمن كتابة البيانات فورًا إلى التخزين. Cache Coherence (قواعد اتساق نسخ الذاكرة المؤقتة بين الأنوية) تحافظ على رؤية معقولة بين Cores لكنها لا تستبدل Locks وAtomic Operations (عمليات تظهر كوحدة غير قابلة للتجزئة بالنسبة للتزامن المحدد) في البرامج المتزامنة.

## فك أسماء التنفيذ وجرّب القياس

**Fetch–Decode–Execute** يعني جلب التعليمة، وفهم نوع العملية والبيانات المطلوبة، وتنفيذها. **Floating point** تمثيل يسمح بأعداد كسرية بدقة محدودة. **Vector** مجموعة قيم تنفذ عليها عملية معًا، و**Branch** انتقال لمسار تعليمات حسب شرط. **Serial** جزء تنفذ خطواته بالتتابع.

**SIMD (Single Instruction Multiple Data؛ تطبيق تعليمة على عدة عناصر بيانات)** تعليمة واحدة تعمل على عدة عناصر. ده مختلف عن تشغيل أنوية متعددة لتدفقات تعليمات مستقلة. في GPU، كلمة **Kernel** تعني برنامج حساب نرسله لوحداته، مش نواة نظام التشغيل. **Branch divergence** اختلاف مسار عناصر تعمل معًا مما قد يقلل الاستفادة من التوازي. **Unified memory** طريقة تعرض ذاكرة بصورة موحدة للبرنامج، لكنها لا تلغي كلفة انتقال البيانات دائمًا.

لو 50% من وقت عمل لا يمكن تقسيمه، تسريع النصف الآخر بلا حد لن يجعل البرنامج أسرع من الضعف: الزمن يبدأ 100، ويبقى على الأقل 50. ده مثال **قانون أمدال** الذي يبين حد التسريع.

**تدريب قياس محلول:** شغّل مهمة تمهيدًا Warm-up (تشغيل تمهيدي قبل القياس لتقليل أثر البداية)، ثم سجل خمس مدد تحت نفس الشروط: 9،10،10،11،30 مللي ثانية. الوسيط Median (الوسيط: القيمة الوسطى بعد ترتيب القياسات) هو 10 بعد الترتيب؛ المتوسط 14. اختلافهما ينبهك لتذبذب أو قيمة بعيدة. لا تحذف قياس30 بلا تفسير، وسجّل حجم البيانات وكلفة نقلها أيضًا.
