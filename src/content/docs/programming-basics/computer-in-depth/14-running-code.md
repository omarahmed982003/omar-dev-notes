## من الطلب لخطوات تقدر تختبرها

لو حد قال لك «اعمل برنامج يحدد الطالب ناجح ولا راسب»، الجملة دي لسه ناقصة. إيه الدرجة المسموح بيها؟ والنجاح من كام؟ ونعمل إيه لو الدرجة خارج المدى؟

**Requirement — متطلب** وصف للسلوك المطلوب. هنستخدم اتفاقًا واضحًا: الدرجة عدد من 0 إلى 100، والنجاح يبدأ من 50؛ غير كده نرفض المدخل.

## الخوارزمية غير الكود

**Algorithm — خوارزمية** خطوات محددة لحل مشكلة، مستقلة عن لغة البرمجة. **Code — كود** تنفيذ الخطوات بقواعد لغة معينة.

**Pseudocode — شبه كود** كتابة بشرية منظمة للخطوات من غير الالتزام بقواعد لغة تنفيذ. المثال ده ورقي، مش أمرًا يتشغّل:

```text
READ grade
IF grade < 0 OR grade > 100
    REPORT invalid
ELSE IF grade >= 50
    REPORT passed
ELSE
    REPORT failed
```

READ تعني استقبل القيمة، وIF تعني اختبر شرطًا، وOR تعني إن تحقق أي بديل يكفي. ELSE تعني الطريق البديل لما الشرط السابق ما يتحققش.

**Flowchart — مخطط تدفق** رسم لنفس الخطوات: بداية، إدخال، قرار له طريقان، نتيجة، نهاية. قيمة الرسم في تتبع القرار، مش حفظ شكل الأسهم.

## امشِ بإيدك قبل ما تشغّل

**Dry run — تتبع يدوي** إنك تمرر مدخلًا خلال الخطوات وتسجل القرار في كل مرحلة. عند الدرجة 50، شرط الرفض لا يتحقق، ثم شرط النجاح يتحقق، فتظهر «ناجح».

| المدخل | المتوقع حسب الاتفاق | السبب |
|---|---|---|
| -1 | غير صالح | أقل من الحد |
| 0 | راسب | داخل المدى وأقل من 50 |
| 49 | راسب | قبل حد النجاح |
| 50 | ناجح | يساوي حد النجاح |
| 100 | ناجح | آخر قيمة صالحة |
| 101 | غير صالح | تجاوز الحد |

**Edge case — حالة طرفية** مدخل عند حد مهم أو حالة غير معتادة. نجاح 70 وحدها لا يثبت إن شرط 50 صحيح، ولا إن البرنامج بيرفض 101.

لو البيانات جاية كنص من مستخدم، تحويلها لعدد والتحقق من شكلها جزء إضافي من العقد؛ ما تفترضش إن أي نص يتحول لدرجة صالحة.

## مين بيحوّل الخطوات لتنفيذ؟

**Source code — الكود المصدري** ملف مكتوب بلغة يفهمها المبرمج. **Compiler — مترجم** يحوّل تمثيلًا لتمثيل أقل مستوى، و**Interpreter — مفسر** ينفذ تعليمات أو تمثيلًا أثناء التشغيل.

**Runtime** المكونات اللي بتدير تنفيذ كود اللغة، زي إدارة memory والتعامل مع الأخطاء. المسار ممكن يجمع compilation وinterpretation؛ مش اختيارًا ثابتًا بين عالمين.

**JIT — Just-In-Time compilation** تحويل بعض العمل إلى machine code أثناء تنفيذ البرنامج. وجودها أوفائدتها بيعتمد على تنفيذ اللغة والإعدادات والحمل.

في نموذج PHP شائع: ملف المصدر يتحلل ويترجم لتعليمات وسيطة، ثم بيئة PHP تنفذها. في برنامج مترجم مسبقًا، خطوة بناء تنتج ملفًا تنفيذيًا يشغّله النظام. التفاصيل في [السوفتوير وruntime](/programming-basics/computer-in-depth/software-and-runtime/).

اختيار اللغة يتبع المجال والمكتبات والفريق والأداء والتوزيع؛ مفيش «أفضل لغة» لكل المشاكل. والترجمة المسبقة أو JIT مش شهادة إن منطق البرنامج صحيح.

## أول تنفيذ: اختياري بعد تجهيز PHP

ما نطلبش كتابة كود قبل أساسيات اللغة. تقدر تكتفي بالتتبع اليدوي هنا، وترجع للمثال في أول دروس PHP.

`$grade` متغير يحمل الدرجة. `if` تختار الطريق بشرط، و`||` معناها «أو»، و`>=` تعني «أكبر من أو يساوي». `echo` تعرض النص و`PHP_EOL` تنهي السطر.

احفظ الملف الجديد باسم `grade.php` داخل التدريب؛ المثال لا يغيّر ملفات غيره:

```php
<?php
$grade = 50;
if ($grade < 0 || $grade > 100) {
    echo 'invalid', PHP_EOL;
} elseif ($grade >= 50) {
    echo 'passed', PHP_EOL;
} else {
    echo 'failed', PHP_EOL;
}
```

شغّل `php grade.php`. المتوقع `passed`. غيّر الدرجة إلى 49 ثم -1: المتوقع `failed` ثم `invalid`.

لاحظ ترتيب التحقق قبل قرار النجاح: لو بدأت بنجاح كل قيمة أكبر من 50، ممكن تقبل 101 بالغلط.

## الخلاصة

حدد المدخل والمخرج والقواعد، تتبع الحالات، ثم اكتب التنفيذ. الترجمة والتشغيل لا يعوضان فهم المشكلة.
