اختبار الكود يقارن سلوكه بوعده، وGit يحفظ تاريخ الملفات. هنفصل المهمتين: اكتب المتوقع مستقلًا، شغّل الحالة، ثم ابحث عن أول خطوة تختلف.


## اكتشاف سبب الخطأ

**Debugging — تشخيص الخطأ وإصلاحه** يبدأ بتجربة تقدر تكررها:

1. أعد المشكلة بمدخل ثابت.
2. اكتب النتيجة المتوقعة Expected والنتيجة الفعلية Actual.
3. حدد آخر نقطة كانت صحيحة.
4. اجمع دليلًا من Logs، سجلات الأحداث، وDebugger، أداة توقف التنفيذ وتعرض القيم، وTests، اختبارات تقارن النتائج بالمطلوب.
5. ضع فرضية واحدة واختبرها بتغيير صغير.
6. أصلح السبب وأضف Regression Test (اختبار لحالة عطَل سابق حتى نلاحظ رجوعه).

`git bisect` يستطيع البحث الثنائي في التاريخ إذا عرفت Commit جيدة وأخرى سيئة، بشرط وجود طريقة تميّز النجاح من الفشل.

## أنواع الاختبارات

- **Unit test — اختبار وحدة:** يفحص منطقًا صغيرًا معزولًا.
- **Integration test — اختبار تكامل:** يفحص تعاون مكونات، مثل البرنامج وقاعدة البيانات أو نظام الملفات.
- **End-to-end test — اختبار رحلة كاملة:** ينفذ خطوات مستخدم عبر النظام.
- **Regression test — اختبار عدم رجوع عطل:** يعيد حالة كشفت عطلًا سابقًا ليلفت النظر لو رجع؛ نجاحه ليس برهانًا أن كل الأعطال مستحيلة.

الاختبار الجيد يرتب **Arrange–Act–Assert**، أي جهز البيانات، نفذ العملية، ثم قارن بالمطلوب، وله سبب فشل واحد واضح، ولا يعتمد على وقت أوشبكة عشوائية بلا تحكم.
