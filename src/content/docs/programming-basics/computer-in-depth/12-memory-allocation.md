## المكان غير العمر

تخيل برنامج بيحسب سعر طلب. ناتج وسيط ممكن ما نحتاجوش بعد الحساب، لكن قائمة الطلبات لسه مطلوبة. **Allocation — تخصيص ذاكرة** توفير مساحة للبيانات؛ **Lifetime — عمر البيانات** المدة اللي تفضل فيها صالحة للاستخدام.

المطلوب من [درس RAM](/programming-basics/computer-in-depth/05-ram-memory-buffers/) إنك تفرق بين **Address space — مساحة عناوين العملية** و RAM الفعلية. تخصيص مساحة مش وعد إن كل صفحاتها بقت موجودة في RAM فورًا.

## Stack و Heap: تنظيم، مش شرائح مختلفة

**Function — دالة** جزء كود ينفذ مهمة وقد يستقبل مدخلات ويعيد نتيجة. **Call — استدعاء** بدء تنفيذ function؛ **Return — رجوع** إكمالها والعودة لموضع من استدعاها.

**Stack — مكدس** تنظيم «آخر داخل، أول خارج». عند تتبع الاستدعاءات، function الأخيرة التي دخلت ترجع قبل التي نادتها. **Stack frame — إطار استدعاء** معلومات لاستدعاء معين، زي موضع الرجوع وحالة التنفيذ وفق اللغة.

**Heap — مساحة تخصيص ديناميكي** تسمح ببيانات لا يرتبط عمرها مباشرة باستدعاء واحد. **Reference — وسيلة وصول لبيانات** معناها هنا إمكانية الوصول لقيمة في المثال الورقي، مش قاعدة خاصة لتمرير القيم في PHP.

الـ Stack والـ Heap مش قطع RAM منفصلة، ومش قاعدة إن كل متغير محلي لازم يكون فعليًا على Stack. **Runtime — بيئة تنفيذ اللغة** قد تحسن التخزين أو تنقل البيانات؛ هنستخدم نموذجًا عامًا للتفسير، مش خريطة PHP حرفية.

### تتبع ورقي لدالتين وقيمة واحدة

الكود الرئيسي يستدعي دالة اسمها makeReport؛ هنسميها A. وهي تستدعي makeTitle؛ هنسميها B. B تجهز نص عنوان تقرير، ثم ترجعه لـ A، و A ترجعه للكود الرئيسي.

نسمي مساحة النص **H1**؛ ده اسم توضيحي، مش عنوانًا حقيقيًا. في النموذج نفترض إن الرجوع يمرر وسيلة وصول لنفس البيانات، من غير إنشاء نسخة جديدة.

اقرأ قائمة الإطارات من الأقدم للأحدث: آخر اسم هو قمة المكدس، يعني الاستدعاء الذي يعمل الآن أو ينتظر إكمال ما بداخله.

| اللحظة | إطارات الاستدعاء | حالة النص H1 |
|---|---|---|
| الرئيسي يستدعي A | `main, A` | لم يُنشأ بعد |
| A تستدعي B، و B تنشئ النص | `main, A, B` | B تستطيع الوصول إليه |
| B ترجع النتيجة إلى A | `main, A` | إطار B انتهى، لكن A احتفظت بوسيلة الوصول |
| A ترجع النتيجة للرئيسي | `main` | إطار A انتهى، والرئيسي ما زال يصل للنص |
| الرئيسي يتخلى عن آخر وسيلة وصول | `main` | قد يصبح النص قابلًا للاسترجاع حسب قواعد البيئة |

إذن **انتهاء إطار الاستدعاء غير انتهاء كل بيانات استُخدمت داخله**. إطار B يحمل معلومات رجوعها؛ النص H1 في النموذج له عمر يستمر لأن الطرف المستدعي ما زال يحتفظ به.

في تنفيذ لغة حقيقي، قيمة قد تُنسخ أو تشارك تمثيلًا داخليًا أو تُخزن بتنظيم مختلف. الجدول يثبت علاقة العمر وإمكانية الوصول، مش إن PHP يضع كل نص على Heap وكل متغير على Stack بالطريقة دي.

### وقف التتبع واختبره

1. بعد رجوع B وقبل رجوع A، هل إطار B موجود؟ وهل H1 انتهى؟
2. بعد رجوع A، مين يحتفظ بالنتيجة؟
3. هل التخلي عن آخر وسيلة وصول يثبت إن Operating System استرجع RAM فورًا؟

1. إطار B انتهى في النموذج؛ H1 مستمر لأن A تصل إليه.
2. الكود الرئيسي، وليس إطار A الذي انتهى.
3. لأ؛ توقيت الاسترجاع وإعادة استخدام الكتل وإعادتها للنظام أمور مختلفة.

## مين بيحدد إن البيانات لسه مطلوبة؟

زي H1 في التتبع، لو قائمة ما زال البرنامج يقدر يوصل لها، انتهاء function اللي أضافت عنصرًا مش سبب كافي لحذفها.

**Managed memory — ذاكرة مُدارة** بيئة اللغة بتدير جوانب من عمرها. **Garbage collection — جمع المهملات** آليات لاسترجاع بيانات لم تعد مطلوبة وفق قواعد التنفيذ؛ بعض البيئات تستخدم عد المراجع ومعالجة الدورات، مش أسلوبًا واحدًا لكل اللغات.

وجود جامع مهملات مش حماية من **Retention — احتفاظ غير لازم**. لو برنامج طويل التشغيل بيضيف بيانات لقائمة أو **Cache — نسخة لإعادة الاستخدام** من غير حد، البيانات قد تفضل قابلة للوصول وتكبر الذاكرة.

تفاصيل zval وجامع المهملات و OPcache الخاصة بـ PHP مكانها مرحلة تنفيذ PHP المتعمقة؛ مش شرط قبل أول برنامج.

## إيه اللي ممكن يفشل؟

**Allocator — مخصص الذاكرة** جزء يدير **Blocks — كتل مساحات** ويعيد استخدامها. تحرير بيانات قد يسمح بإعادة استخدام الكتلة داخل البرنامج، من غير رجوعها فورًا لOperating System.

| المشكلة | معناها | مثال تشخيصي |
|---|---|---|
| Leak — تسرب | موارد تفضل محجوزة بعد انتهاء الحاجة الفعلية | كل طلب يسيب حجزًا لا يُحرر |
| Fragmentation — تجزؤ | مساحات موزعة أو هدر يصعّبان تلبية حجز مناسب | فيه فراغ إجمالي، لكن شكل الكتل غير مناسب |
| Stack overflow — تجاوز المكدس | استدعاءات أعمق من المساحة المتاحة | Recursion، دالة تستدعي نفسها، من غير توقف مناسب |
| OOM، Out of memory | فشل توفير الذاكرة المطلوبة | فشل حجز أو إنهاء العملية وفق سياسة النظام |

لا تجرّب استهلاك الجهاز كله لإثبات OOM. كذلك **Demand paging — توفير صفحات عند الحاجة** و**Overcommit — سياسة قبول حجوزات تتجاوز بعض الموارد المتاحة لحظيًا** يفسران ليه نجاح الحجز مش ضمانًا لكل وصول لاحق.

## اقرأ العداد الصح

**Resident memory — الذاكرة المقيمة** الصفحات الموجودة حاليًا في RAM وفق حساب النظام. **RSS — Resident Set Size** قياس شائع لذاكرة العملية المقيمة، مش حجم متغيراتها فقط.

**Working set — مجموعة العمل** قد تعني الصفحات النشطة خلال فترة في النموذج النظري؛ عداد Working Set في Windows يصف الصفحات المقيمة للعملية. اقرأ تعريف أداة القياس بدل افتراض تطابق الأسماء بين الأنظمة.

**Peak usage — ذروة الاستخدام** أعلى قيمة مرصودة، غير الاستهلاك الحالي. **Native memory — حجز أصلي خارج بعض عدادات كائنات اللغة** قد يشمل مكتبات ومكدسات خيوط وصفحات ملفات.

علشان كده عداد ذاكرة PHP وعداد النظام ممكن يختلفا من غير ما واحد فيهم يكون غلطًا.

### تجربة PHP اختيارية ومحدودة

بعد تجهيز PHP وفهم variables، `memory_get_usage` دالة بتعرض بايتات تتبعها إدارة ذاكرة PHP؛ مش كل RSS. `str_repeat` تنتج نصًا متكررًا، و`unset` تزيل variable في المثال.

احفظ ملفًا جديدًا `memory-lifetime.php` وشغّله بـ`php memory-lifetime.php`. الحجز هنا 1 MiB فقط، لا يكتب ملفات ولا يقيس أداء جهازك:

```php
<?php
echo memory_get_usage(), PHP_EOL;
$payload = str_repeat('x', 1024 * 1024);
echo memory_get_usage(), PHP_EOL;
unset($payload);
echo memory_get_usage(), PHP_EOL;
```

المتوقع زيادة العداد بعد إنشاء النص، وانخفاض بعد إزالة مرجعه الوحيد في المثال. مش مطلوب أرقام ثابتة أو تطابق مقدار الزيادة تمامًا، ولا نستنتج إن كل الانخفاض رجع فورًا لOperating System.

## تمرين من غير كود

ارسم عمليتين، لكل واحدة مساحة عناوين. الأولى تحتفظ بقائمة تكبر، والتانية تفتح وتغلق ملفًا. أيهما قد تكبر ذاكرتها رغم وجود جامع مهملات؟ وهل إغلاق الثانية يعني اختفاء ملفها من القرص؟

<details>
<summary>التفسير بعد المحاولة</summary>

القائمة القابلة للوصول قد تكبر بلا حد؛ جامع المهملات لا يقرر إنك بطلت تحتاج عنصرًا ما زلت تحتفظ به. إنهاء العملية يحرر مواردها وفق النظام، لكنه لا يحذف ملفًا محفوظًا لمجرد الإغلاق.

</details>
