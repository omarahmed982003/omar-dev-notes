هنتتبع قيمة محلية، وبعدها بيانات نحتاجها لمدة أطول. المطلوب فهم معنى عنوان في الذاكرة من الدرس السابق.

## قيمة قصيرة العمر وبيانات نحتفظ بها

تخيل دالة تحسب سعرًا: المدخل والنتيجة الوسيطة مطلوبان أثناء الاستدعاء. عند انتهائه يمكن إنهاء عمر البيانات المحلية حسب قواعد اللغة. أما قائمة المشتريات فتحتاجها بعد انتهاء دالة الإضافة. **Allocation — حجز ذاكرة** توفير مكان للبيانات؛ **Lifetime — عمر البيانات** الفترة التي تكون فيها صالحة للاستخدام. المكان والعمر ليسا نفس السؤال.

Stack، أو المكدس، ينظم عادة بيانات استدعاءات الدوال. Heap، أو مساحة الحجز الديناميكي، تسمح بأعمار أكثر مرونة. اللغة والتنفيذ قد يحسنان مكان التخزين؛ لا تفترض أن كل قيمة محلية حتمًا موجودة فعليًا على المكدس.

**سؤال:** انتهاء دالة الإضافة لا يعني حذف قائمة ما زال البرنامج يحتاجها. مَن يقرر انتهاء عمرها؟ قواعد اللغة وطريقة إدارة الذاكرة والمراجع إليها، كما نفصّل تحت.

## Stack وHeap

Stack Frames (سجلات استدعاء تحمل حالة الدالة وما يلزم العودة منها) تحفظ معلومات استدعاءات الدوال ومتغيرات محلية وفق Runtime (بيئة تنفيذ اللغة والخدمات التي تحتاجها؛ غير معنى وقت التشغيل الزمني) واللغة، وتُزال عادة عند العودة. Heap (مساحة تخصيص بيانات لا يرتبط عمرها مباشرة باستدعاء واحد) تستخدم للكائنات والبيانات ذات العمر الديناميكي. Stack (مكدس: تنظيم آخر داخل أول خارج، ويُستخدم غالبًا لتتبع استدعاءات الدوال) Overflow ينتج غالبًا من Recursion (استدعاء الدالة لنفسها مباشرة أو عبر دوال أخرى) عميق أوإطار ضخم؛ Heap قد تعاني Leak (تسرب: موارد تظل محجوزة بعد انتهاء الحاجة إليها) أوFragmentation (تجزؤ: مساحة موزعة أو مهدرة تصعّب تلبية طلبات الحجز) أوOOM (Out Of Memory؛ عدم كفاية الذاكرة المطلوبة).

هذه أسماء لمناطق من Address Space، وليست شرائح RAM منفصلة. نظام التشغيل قد لا يمنح Physical Memory لحظة الحجز نفسها بسبب Demand Paging وOvercommit policies.

## Allocation وLeak وFragmentation وOOM

Allocator (جزء برمجي يدير حجز كتل الذاكرة وإعادة استخدامها) يدير Blocks ويعيد استخدامها. Leak يعني بقاء Reference (مرجع يتيح الوصول لكائن أو بيانات؛ وجوده قد يبقيها مطلوبة) أوحجز لم يعد مفيدًا. Fragmentation تعني وجود مساحة لكنها موزعة بما يصعب تلبية Block مناسب أو يزيد الهدر. عند نفاد الذاكرة قد يفشل Allocation (حجز مساحة ذاكرة للاستخدام) أو يقتل النظام Process وفق سياسته.

راقب Working Set (الصفحات التي يستخدمها البرنامج بنشاط خلال فترة القياس) وResident Memory (الجزء الموجود حاليًا في الذاكرة الفعلية وفق حساب النظام) وPeak Usage (أعلى استهلاك رُصد خلال فترة)، لا حجم المتغيرات النظري فقط. Garbage Collector (جامع المهملات الذي يسترجع ذاكرة لم تعد قابلة للوصول) يساعد في لغات Managed لكنه لا يصلح Retention مقصودة أوCaches بلا حدود.


**Managed memory** ذاكرة تدير اللغة أجزاء من عمرها، و**Native memory** حجز خارج العدادات المعتادة لذاكرة كائنات اللغة. **Retention** احتفاظ بمراجع لكائنات لا نحتاجها؛ جامع المهملات لا يحذف كائنًا ما زال البرنامج يحتفظ به. **RSS (Resident Set Size؛ مقدار من ذاكرة العملية موجود حاليًا في RAM وفق قياس النظام)** يقيس الذاكرة المقيمة وفق النظام؛ قد يزيد بسبب مكدسات خيوط أو حجز مكتبة أو صفحات مرتبطة بملف حتى لو عداد heap ثابت.
