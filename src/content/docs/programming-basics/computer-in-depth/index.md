لما برنامج يتأخر أو يستهلك ذاكرة أو يفشل يفتح ملف، حفظ قواعد اللغة مش كفاية علشان تعرف السبب. محتاج تعرف البرنامج بيطلب إيه من الجهاز وOperating System بيتعامل مع الطلب إزاي.

هنبدأ بالهاردوير بالقدر اللي يخدم المبرمج، وبعدها ندخل في السوفتوير والتنفيذ. درس المقدمة بيفرق بين الكود والبرنامج والعملية والـRuntime والمكتبة والـFramework قبل ما تحتاج تستخدم المصطلحات دي في Operating System.

## الأساس المطلوب والتعمق الاختياري

هدف أول مرور إنك تفسر تشغيل برنامج وموارده: أدوار الجهاز، السوفتوير، العملية والصلاحيات، البيانات، الذاكرة وعمرها، الملفات، والطرفية والبيئة.

تفاصيل وصلات الهاردوير وحساب ترجمة الصفحات واتساق Cache وتوازي GPU تعمق موجود في موضوعه؛ مش شرطًا قبل أول كود. تجارب PHP اختيارية إلى أن تجهز اللغة، ولك بديل ملاحظة أو تتبع ورقي.

## مشروع الجزء: راقب برنامجًا وفسّر اللي حصل

المشروع تقرير ملاحظات، مش كتابة برنامج جديد. اختار محرر نصوص وملف تدريب جديدًا. لا تنه عمليات النظام ولا تغير صلاحيات أو PATH دائمًا.

1. ارسم دور CPU وRAM والتخزين وقت فتح الملف وحفظه وإغلاقه.
2. سجّل ملاحظتين من Task Manager عن المعالج والذاكرة، واشرح ليه مفيش رقم ثابت لازم يظهر.
3. اقرأ ملف التدريب بمسار نسبي ومطلق، ثم غيّر مجلد العمل وفسّر الفرق.
4. اعرض APP_ENV غير السري وحدد هل التغيير دائم، وهل وصل لعمليات قديمة.
5. شخّص أمرًا غير معروف أو مسار ملف غلط من رسالة أو مثال ورقي؛ لا تعطل التثبيت ولا تغيّر أذونات ملفات حقيقية.
6. ارسم طبقات الكتابة وفسّر ليه رسالة Saved وحدها مش ضمانًا لكل فشل.
7. كرر ملاحظة واحدة مستقلًا، وسجّل المتوقع والفعلي وتفسير الفرق.

دليل الفهم تفسير السبب وحدود الملاحظة، مش صورة أرقام فقط. درجات التقييم والتقدم لهم ملفات خاصة؛ قراءة الكارد لا تمنح نجاحًا تلقائيًا.

## اربط اللي بتشوفه بالسبب

قبل تشغيل المثال توقع النتيجة، وبعده غيّر مدخلًا واحدًا وراجع تفسيرك. في مثال الملف، حدد العملية وهويتها والمسار والناتج المطلوب. في مثال التأخير، اسأل هل البرنامج بيحسب فعلًا ولا مستني موردًا؟

بعد فهم العملية والذاكرة والموارد، انتقل إلى [الشبكات والويب](/programming-basics/networking-next/) علشان تتبع التواصل بين البرامج.
