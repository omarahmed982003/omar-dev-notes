## الفكرة العامة

الكمبيوتر نظام يستقبل بيانات، ينفذ عليها تعليمات، ينتج نتيجة، وقد يحفظها. فهم هذه الدورة يربط بين البرنامج والذاكرة والمعالج وأجهزة الإدخال والإخراج.

## المفاهيم الأساسية

- البيانات حقائق خام؛ المعلومات بيانات جرى تنظيمها أو تفسيرها؛ والمعرفة هي القدرة على استخدامها لاتخاذ قرار.
- Hardware هو المكوّن المادي، وSoftware هو التعليمات التي تدير هذا المكوّن.
- البرنامج سلسلة تعليمات، أما العملية Process فهي نسخة من برنامج قيد التنفيذ.
- الذاكرة RAM سريعة ومؤقتة، بينما التخزين دائم نسبيًا وأبطأ.
- نموذج IPO يبسّط أي برنامج إلى مدخلات ومعالجة ومخرجات، مع تخزين عند الحاجة.

## مثال تطبيقي

عند إرسال رسالة: لوحة المفاتيح تنتج Input، التطبيق يعالج النص ويشفّره، الشبكة تنقله، ثم يظهر Output عند المستلم وقد يُحفظ في Storage.

## تصحيح مفاهيم وأخطاء شائعة

- المعالج لا “يفهم” نية المستخدم؛ ينفذ تعليمات محددة فقط.
- الملف على القرص لا يصبح برنامجًا يعمل إلا بعد تحميله وتشغيله.

## دورة الجلب وفك الترميز والتنفيذ

ينفّذ المعالج التعليمات في دورة متكررة: يجلب التعليمة من الذاكرة **Fetch**، ويفك معناها ويحدد المعاملات **Decode**، ثم ينفذ العملية ويحدّث السجلات أو الذاكرة **Execute**. هذه صورة تعليمية مبسطة؛ المعالجات الحديثة تستخدم خطوط تنفيذ متوازية وذاكرة مخبأة وتوقع الفروع، لكن النموذج يوضح لماذا يحتاج البرنامج إلى تعليمات وبيانات وحالة تنفيذ.

## هرم الذاكرة

| المستوى | السرعة التقريبية | السعة | الاستخدام |
|---|---|---|---|
| Registers | الأعلى | صغيرة جدًا | القيم التي تعمل عليها وحدة التنفيذ الآن |
| CPU Cache | عالية جدًا | صغيرة | نسخ قريبة من البيانات والتعليمات كثيرة الاستخدام |
| RAM | عالية | متوسطة | البرامج والبيانات النشطة |
| SSD/HDD | أبطأ | كبيرة | الملفات والبرامج بعد إغلاقها |

قرب البيانات من المعالج يسرّع الوصول إليها. لذلك قد يكون ترتيب البيانات وطريقة الوصول إليها مهمين للأداء، حتى عندما تنفذ الخوارزمية العدد نفسه من الخطوات تقريبًا.

## ماذا يحدث عند فتح برنامج؟

يطلب المستخدم التشغيل، فيتحقق نظام التشغيل من الملف والصلاحيات، وينشئ Process ومساحة ذاكرة، ويحمّل الصفحات المطلوبة، ثم يحدد نقطة البداية. بعد ذلك يوزع المجدول وقت المعالج بين العمليات، وتتعامل Drivers مع الشاشة والقرص والشبكة.

## Registers وALU وControl Unit

تحتفظ Registers بالقيم التي يعمل عليها المعالج الآن، وهي أسرع كثيرًا من RAM. تنفذ ALU العمليات الحسابية والمنطقية، بينما تدير Control Unit جلب التعليمات وفكها وتوجيه تنفيذها. يحدد Program Counter عنوان التعليمة التالية، ويتغير عند الانتقال أو استدعاء دالة.

تقيس Clock عدد النبضات، لكنها لا تكفي وحدها لمقارنة معالجين؛ يؤثر عدد التعليمات المنفذة في الدورة وبنية Cache وعدد الأنوية. الـCore وحدة تنفيذ مستقلة نسبيًا، وHardware Thread يسمح للنواة بالاحتفاظ بأكثر من سياق تنفيذ، لكنه ليس مساويًا لنواة كاملة.

## Stack وHeap وVirtual Memory

يستخدم البرنامج Stack عادة لاستدعاءات الدوال والمتغيرات المحلية قصيرة العمر. ويستخدم Heap للتخصيص الديناميكي الذي قد يستمر عبر نطاقات مختلفة. هذه صورة تعليمية شائعة وليست ضمانًا لمكان كل كائن، لأن المترجم يستطيع التحسين.

تمنح Virtual Memory كل Process مساحة عناوين تبدو مستقلة. يقسم النظام الذاكرة إلى Pages ويربط العناوين الافتراضية بإطارات فعلية. إذا احتاج البرنامج صفحة غير موجودة في RAM يحدث Page Fault ويجلبها النظام أو ينشئها. كثرة النقل بين RAM والتخزين تسبب بطئًا شديدًا يسمى Thrashing.

## Process وThread وContext Switch

الـProcess برنامج يعمل وله مساحة عناوين وموارد. تشترك Threads داخل العملية غالبًا في الذاكرة والملفات، لكن لكل Thread Stack وحالة تنفيذ. يوزع Scheduler وقت المعالج بينها. عند Context Switch يحفظ النظام حالة تنفيذ ويستعيد أخرى، لذلك التبديل له تكلفة.

الوصول المتزامن إلى بيانات مشتركة قد ينتج Race Condition عندما تعتمد النتيجة على ترتيب التنفيذ. معالجة ذلك تحتاج مزامنة وتصميمًا يقلل الحالة المشتركة، وليس مجرد زيادة عدد Threads.

## خلاصة

افهم العلاقة بين الفكرة ومدخلاتها ونتيجتها، ثم اختبرها بحالات عادية وحدّية وغير صالحة. القدرة على التفسير والتطبيق أهم من حفظ الصياغة.
