اسم النمط مش حل. هنمشي على بيانات صغيرة ونشوف إيه اللي نحتفظ بيه، وإيه اللي يسمح لنا نستبعد احتمالات. محتاج تكون فاهم قائمة، موضع عنصر، وحلقة؛ تقدر تتبعها ورقيًا قبل كود PHP الاختياري.

## الأول جرّب الحل المباشر

**Brute force — تجربة كل الاحتمالات** يبدأ بكل زوج مختلف من القائمة. مع n عناصر فيه `n(n−1)/2` زوجًا: 45 زوجًا لعشرة عناصر، و 4950 لمئة عنصر.

ده نمو تربيعي `O(n²)`. مرور واحد نمو خطي `O(n)`، وعدد عمليات لا يزيد مع n هو `O(1)`؛ مش معناه ثانية واحدة. القواعد والنمو اتشرحوا في [مقارنة الحلول](/programming-basics/08-problem-solving-algorithms/).

**Simulation — محاكاة** تطبيق قواعد المسألة خطوة بخطوة، زي تحديث رصيد افتراضي بعد كل حركة. مش كل مسألة تحتاج نمطًا أسرع من التنفيذ المباشر.

## عدّ التكرار أو احتفظ بالمميز

في `[2,1,2,3]`، **Frequency map — جدول تكرار** يربط القيمة بعدد ظهورها: `{2:2,1:1,3:1}`. النقطتان تربطان المفتاح بعداده.

لو السؤال «ظهرت القيمة قبل كده؟» فقط، **Set — مجموعة قيم مميزة** تحتفظ بـ `{1,2,3}` بلا عدادات. اختيار البنية يتبع السؤال، مش الاسم الأشهر.

## مجموعات نطاقات من غير إعادة الجمع

**Prefix sum — مجموع من البداية** يحفظ مجموع كل بادئة. لنفس القائمة نبني `P=[0,2,3,5,8]`؛ الصفر الأول يمثل عدم جمع أي عناصر.

مع ترقيم عناصر المسألة من 1، مجموع المواضع 2 إلى 4 هو `P[4]−P[1]=8−2=6`. بنشيل مجموع العناصر اللي قبل النطاق، مش أول عنصر منه.

تجهيز P يحتاج مرورًا واحدًا، وكل سؤال بعدها يحتاج وصولين وطرحًا بدل مرور جديد. ده مفيد لأسئلة كثيرة على بيانات ثابتة؛ تعديل قيمة يغير مجاميع البادئات المتأثرة، فلا تتعامل مع التحديث كأنه مجاني.

## Two pointers: شوف الحركة فعلًا

**Two pointers — مؤشرا موضع** متغيران يشيران لعنصرين. نبحث عن عنصرين **في موضعين مختلفين** مجموعهما 8 في القائمة المرتبة تصاعديًا `[1,3,5,8]`. الترقيم البرمجي يبدأ من 0.

| left, right | القيمتان | المجموع | القرار |
|---|---|---: |---|
| 0, 3 | 1 و 8 | 9 | أكبر من 8؛ حرّك right إلى 2 |
| 0, 2 | 1 و 5 | 6 | أقل من 8؛ حرّك left إلى 1 |
| 1, 2 | 3 و 5 | 8 | وجدنا الموضعين 1 و 2 |

ليه الحركة آمنة؟ عند 1+8 الأكبر من الهدف، أي قيمة بدل 1 من العناصر الباقية هتخلي الجمع مع 8 أكبر أو مساويًا 9، فـ 8 مش طرفًا لحل. وعند 1+5 الأصغر من الهدف، أي قيمة بدل 5 في النطاق الباقي لا تتجاوز 5، فـ 1 مش طرفًا لحل.

الترتيب هو اللي يبرر الاستبعاد. من غيره، تحريك الطرفين بنفس القاعدة ممكن يضيع الحل.

## الغائب مش معناه «اجمع العنصر بنفسه»

مع نفس القائمة وهدف 10:

| left, right | المجموع | بعد القرار |
|---|---: |---|
| 0, 3 | 9 | left=1 |
| 1, 3 | 11 | right=2 |
| 1, 2 | 8 | left=2؛ توقف |

وصل المؤشران لنفس الموضع. الشرط **`left < right`** يمنع استعمال 5 مرتين من خانة واحدة. النتيجة «لا يوجد زوج»، مش 5+5.

لو القائمة `[5,5]`، فالموضعان 0 و 1 مختلفان، ويصح تكوين 10. القيم المتساوية مسموحة؛ الممنوع تكرار **الموضع** نفسه.

## تجربة PHP كاملة واختيارية

المطلوب PHP 8.1+ ومعرفة arrays و functions و while من [مسار PHP](/php/). احفظ `pairs.php` وشغل `php pairs.php`؛ لا توجد كتابة ملفات.

**العقد:**  قائمة متصلة مفاتيحها 0 ثم 1 وهكذا، مرتبة تصاعديًا، عناصرها أعداد صحيحة بين−1000000 و 1000000، والهدف صحيح بين−2000000 و 2000000. الحدود الصغيرة تجعل جمع عنصرين آمنًا على PHP 32 و 64 بت؛ دي حدود التدريب، مش قانونًا للخوارزمية.

`array_is_list` تفحص شكل القائمة، و `count` عددها. `?array` تعني نتيجة array أو `null`؛ null هنا «لا يوجد زوج». `++` تزيد الموضع و `--` تنقصه. الإرجاع موضعان يبدأ ترقيمهما من 0، مش القيمتين. مخالفة شكل القائمة أو نوع عنصر أو الترتيب أو الحدود تثير `InvalidArgumentException`. لو باراميتر الدالة نفسه مش مطابق لنوع array أو int المعلن، ممكن يثير **TypeError — خطأ عدم مطابقة النوع** بدلًا منها.

~~~php
<?php
declare(strict_types=1);

function pairSumSorted(array $values, int $target): ?array
{
    if (!array_is_list($values) || $target < -2_000_000 || $target > 2_000_000) {
        throw new InvalidArgumentException('Invalid list or target');
    }

    foreach ($values as $index => $value) {
        if (!is_int($value) || $value < -1_000_000 || $value > 1_000_000) {
            throw new InvalidArgumentException('Invalid value');
        }

        if ($index > 0 && $values[$index - 1] > $value) {
            throw new InvalidArgumentException('List must be sorted');
        }
    }

    $left = 0;
    $right = count($values) - 1;

    while ($left < $right) {
        $sum = $values[$left] + $values[$right];

        if ($sum === $target) {
            return [$left, $right];
        }

        if ($sum < $target) {
            $left++;
        } else {
            $right--;
        }
    }

    return null;
}

foreach ([[[1, 3, 5, 8], 8], [[1, 3, 5, 8], 10], [[], 1], [[5], 10]] as [$values, $target]) {
    $pair = pairSumSorted($values, $target);
    echo $target . ':' . ($pair === null ? 'none' : $pair[0] . ',' . $pair[1]) . PHP_EOL;
}
~~~

الخرج المتوقع:

~~~text
8:1,2
10:none
1:none
10:none
~~~

السطران الأخيران لقائمة فارغة وقائمة ذات عنصر واحد. فحص النوع والترتيب يمر على n عناصر، والبحث يحرك مؤشرًا في كل دورة؛ الزمن O(n)، والذاكرة الإضافية O(1) باستثناء المدخل والنتيجة الثابتة. مش بنفرز قائمة المستخدم في الخفاء.

## تعمق اختياري: أسماء أخرى لها عقود مختلفة

**Greedy — اختيار جشع** يختار أفضل خطوة حالية، لكنه محتاج حجة صحة للمسألة؛ [مثال العملات في الدرس التالي](/programming-basics/math-problem-solving/10-greedy-dynamic-programming/) يبين فشله مع فئات معينة.

**Dynamic programming — البرمجة الديناميكية** تحفظ نتائج مسائل أصغر متكررة. في مسائل تحسين النتيجة، لازم علاقة مناسبة بين أفضل الحلول الصغيرة والحل الكامل.

**Recursion — استدعاء ذاتي** دالة تستدعي نفسها لمسألة أصغر مع حالة توقف؛ مش كل استدعاء ذاتي DP. **Divide and conquer — تقسيم ودمج** يحل أجزاء أصغر ثم يدمجها، زي ترتيب نصفي قائمة ودمجهما.

## جرّب مستقلًا

1. تتبع هدف 6 في `[1,3,5,8]`، ثم هدف 4 في نفس القائمة. لازم ترجع موضعين مختلفين.
2. ما نتيجة هدف 10 في `[5]` وفي `[5,5]`؟
3. في `[4,4,2]` احسب تكرار 4، وعدد القيم المميزة، والمجموع، ومجموع الفراغ.
4. لماذا ترفض تجربة PHP قائمة `[3,1,8,5]` أو عنصرًا نصيًا مثل `"hello"` بدل التحريك عليها؟
