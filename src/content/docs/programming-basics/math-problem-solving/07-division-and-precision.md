معاك 17 قطعة وعلب تسع كل واحدة 5. فيه 3 علب ممتلئة، ويتبقى 2. لو عايز تحط **كل** القطع في علب، تحتاج 4. الأسئلة الثلاثة مختلفة، فلازم تختار العملية على أساس السؤال.

مفيش كود مطلوب للحساب اليدوي. مثال PHP الاختياري يحتاج PHP 8+ وتشغيل ملفات الطرفية كما في [مسار PHP](/php/)؛ مش مطلوب تخلص المسار عشان تقرأ الحساب.

## خارج القسمة والباقي

`17 = 3×5 + 2`. العدد 3 **خارج قسمة صحيح**، والعدد 2** باقي**. في PHP نكتب الخارج `intdiv(17,5)`، والباقي `17 % 5`.

علامة `/` في PHP قسمة عادية؛ `17/5` تعطي 3.4، مش 3. كون الطرفين أعدادًا صحيحة مش معناه أن الناتج هيكون صحيحًا.

**القسمة السقفية** هنا عدد مجموعات يسع كل العناصر: نأخذ الخارج الصحيح، ونضيف 1 لو الباقي مش صفر. كده 17 قطعة تحتاج 4 علب، و 15 قطعة تحتاج 3، وصفر قطعة يحتاج صفر علب.

## تجربة PHP كاملة: عدد العلب

احفظ الملف باسم `division.php` داخل مجلد تدريب جديد، ثم شغله بـ `php division.php`. المثال يطبع فقط، ولا يقرأ أو يغير ملفاتك.

**function** خطوات لها اسم ومدخلات وناتج. `int` تعني عددًا صحيحًا، و `return` ترجع الناتج. `%` للباقي، و `===` مقارنة دقيقة، و `? :` تختار قيمة بين بديلين. `foreach` تكرر على الأمثلة.

الشرط `count >= 0` يمنع كمية سالبة، و `size > 0` يمنع حجمًا صفريًا أو سالبًا. `throw` يوقف الحساب بإشارة فشل من نوع `InvalidArgumentException`، معناها إن مدخلات function غير مقبولة.

~~~php
<?php
declare(strict_types=1);

function boxesNeeded(int $count, int $size): int
{
    if ($count < 0 || $size <= 0) {
        throw new InvalidArgumentException('Invalid count or box size');
    }

    return intdiv($count, $size) + ($count % $size === 0 ? 0 : 1);
}

foreach ([[10, 3], [17, 5], [0, 5]] as [$count, $size]) {
    echo $count . '/' . $size . ': ' . boxesNeeded($count, $size) . PHP_EOL;
}
~~~

الخرج المتوقع:

~~~text
10/3: 4
17/5: 4
0/5: 0
~~~

`strict_types` يجعل استدعاءات النوع الصارم ترفض قيمًا مش من النوع المعلن بدل تحويلها تلقائيًا، و `PHP_EOL` ينهي السطر. الكود يجمع الخارج مع صفر أو واحد؛ مش بيجمع حجم العلبة على كمية ربما قريبة من أقصى عدد مسموح.

صيغة `intdiv(count + size - 1, size)` تصلح أيضًا مع `count` غير سالب و `size` موجب **بشرط ألا يتجاوز الجمع مدى العدد**. كتابة `(count + size - 1) / size` وحدها مش قسمة سقفية في PHP: للمثال 17 و 5 تعطي 4.2. علامة القسمة جزء من العقد، مش تفصيلة شكلية.

## Floor و Ceil و Round

**Floor — الأرضية** أكبر عدد صحيح لا يزيد عن القيمة. **Ceil — السقف** أصغر عدد صحيح لا يقل عنها. **Round — التقريب** يختار الأقرب وفق قاعدة function لحالات التعادل.

| القيمة | floor | ceil |
|---|---: |---: |
| 2.3 | 2 | 3 |
| −2.3 | −3 | −2 |

الأرضية مش معناها «احذف الكسور»: حذف كسر−2.3 نحو الصفر يعطي−2، وده غير الأرضية−3. `intdiv(-7,3)` في PHP يعطي−2؛ Python مع `//` يعطي−3. اذكر اللغة والعملية قبل تعميم قاعدة السالب.

عند التعادل، زي 2.5، قاعدة `round` تعتمد على اللغة وإعداد التقريب. ما تفترضش قاعدة واحدة لكل البيئات.

## الباقي يحوّل الخط إلى دورة

الساعة 23 وبعدها 5 ساعات: `(23+5)%24 = 4`. الدورة طولها 24، والباقي يرجعنا لرقم داخلها. نستخدم نفس الفكرة في الزوجي والفردي، وتوزيع الوقت، والتكرار.

في PHP باقي العدد السالب ممكن يكون سالبًا: `-1 % 24 = -1`. لو العقد محتاج نتيجة من 0 إلى 23، طبّعها بـ `((value % 24)+24)%24`. نفترض طول دورة موجبًا، ونراعي مدى الأعداد عند تطبيق صيغة عامة.

## تعمق اختياري: GCD و LCM

**GCD — أكبر قاسم مشترك** أكبر عدد موجب يقسم عددين صحيحين موجبين بلا باقي. لـ 48 و 18 نستعمل **خوارزمية إقليدس**: كل مرة نستبدل العددين بالقاسم والباقي.

| العملية | الباقي |
|---|---: |
| 48 % 18 | 12 |
| 18 % 12 | 6 |
| 12 % 6 | 0 |

آخر قاسم غير صفري هو 6. سبب الفكرة أن القواسم المشتركة لـ `a,b` هي نفسها لـ `b,a%b`، لحد ما الباقي يختفي.

**LCM — أصغر مضاعف مشترك** أول مضاعف موجب يجمع العددين الموجبين. جرس كل 4 دقائق وآخر كل 6 يجتمعان بعد 12. نحسب لـ 48 و 18: `48÷6×18=144`؛ نقسم على GCD قبل الضرب لتقليل حجم الوسيط، لكن ده مش ضمانًا ضد تجاوز المدى.

لو أحد المدخلين صفر، اتفاق برمجي شائع يجعل LCM صفرًا؛ عالج `(0,0)` قبل أي قسمة. `abs` تعني القيمة المطلقة، أي المسافة عن الصفر. التعامل مع السالب وأقصى قيمة سالبة محتاج عقدًا ومدى نوع معلومين؛ أمثلة القسم موجبة وصغيرة.

## الدقة غير تجاوز المدى

**Floating Point — عدد عشري عائم** تمثيل تقريبي لكثير من الكسور. **الخطأ المطلق** مقدار الفرق عن القيمة المرجعية؛ لو المتوقع 100 والمحسوب 100.2، الخطأ 0.2. **الخطأ النسبي** يقسمه على حجم المرجع، فيكون 0.002، أو 0.2%.

**Tolerance — هامش قبول** فرق صغير نختاره حسب المسألة، مش رقمًا سحريًا ثابتًا لكل المقاييس. المرجع صفر يحتاج معالجة بدل قسمة الخطأ النسبي عليه.

**Overflow — تجاوز المدى** معناه أن الناتج لا يسعه النوع العددي؛ مش خطأ تقريب نعالجه بهامش. حساب فلوس دقيقة قد يناسبه وحدات صحيحة زي القروش مع فحص المدى، أو نوع عشري مناسب، حسب العقد.

## اختبر فهمك

1. احسب خارج 17÷5 وباقيها وعدد العلب، ثم كرر مع 15 و 0.
2. لماذا نقل صيغة `(17+5-1)/5` كما هي إلى PHP لا يعطي عدد العلب؟
3. توقع `boxesNeeded(5,0)` و `boxesNeeded(-1,3)` من العقد، من غير تشغيلهما داخل طلب حقيقي.
4. ما الساعة بعد 5 ساعات من 23؟ وما الأرضية والسقف لـ−2.3؟
