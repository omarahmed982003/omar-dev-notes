في الدرس السابق احتاج العميل إلى عنوان الخادم قبل بدء الاتصال. هنا سنفصل بين شيئين: **IP (Internet Protocol؛ قواعد عنونة الحزم وتوجيهها بين الشبكات، وعنوان IP رقم يحدد واجهة في هذا السياق) هو العنوان الذي يمكن توجيه الحزم إليه، وDNS (Domain Name System؛ نظام يجيب عن أسئلة أسماء النطاقات، ومنها عناوينها) هو النظام الذي يجد العنوان المناسب للاسم**.

## اقرأ شكل نتيجة البحث

شغّل `nslookup example.com`. ده **مثال توضيحي لشكل** الناتج؛ القيم الحقيقية تتغير:

```text
Server:  router.home
Address: 192.168.1.1
Non-authoritative answer:
Name:    example.com
Address: 203.0.113.10
```

أول Server وAddress يخصان الجهة التي أجابت عن السؤال، مش الموقع. Name وAddress بعد Answer يخصان الاسم المطلوب. العنوان203.0.113.10 مخصص للتوثيق هنا، فلا تتوقع الوصول للموقع به. **Non-authoritative** تعني أن الإجابة ليست مباشرة من الخادم صاحب بيانات النطاق؛ لا تعني وحدها أن الإجابة خاطئة. قد ترى أكثر من عنوان أو إصدارًا سادسًا بدل هذه القيم.

## الفكرة: دفتر عناوين موزّع

البشر يتذكرون `example.com` أسهل من رقم، والخدمة قد تنقل خوادمها من غير تغيير الاسم. لكن DNS ليس ملفًا عالميًا واحدًا؛ هو نظام موزّع، وكل جهة تجيب عن الجزء المسؤول عنه.

عنوان IP يعرّف واجهة على شبكة ويسمح للراوترات بتوجيه الحزم:

- `192.168.1.20`: مثال IPv4 (Internet Protocol version 4؛ إصدار عناوين الشبكة ذي32 بتًا) خاص داخل شبكة محلية.
- `203.0.113.10`: عنوان IPv4 مخصص للأمثلة والتوثيق.
- `2001:db8::10`: عنوان IPv6 (Internet Protocol version 6؛ إصدار عناوين الشبكة ذي128 بتًا) مخصص للأمثلة.
- `127.0.0.1` و`::1`: loopback، أي الجهاز نفسه.
- `localhost`: اسم يُحل عادة إلى loopback.

العنوان الخاص داخل المنزل ليس عنوانك العام بالضرورة؛ الراوتر يجري NAT (Network Address Translation؛ تغيير عناوين IP أثناء مرور الحزم بين شبكات) غالبًا. وIP لا يحدد شخصًا أو جهازًا بصورة دائمة، فقد يتغير أو تشترك فيه أجهزة.

## ما الذي يعيده DNS؟

يعيد DNS سجلات ذات أنواع مختلفة:

| Record | معناه |
|---|---|
| `A` | اسم إلى IPv4 |
| `AAAA` | اسم إلى IPv6 |
| `CNAME` | اسم مستعار يشير إلى اسم آخر |
| `MX` | خوادم استقبال البريد للنطاق |
| `TXT` | نصوص تحقق وسياسات |
| `NS` | خوادم الأسماء المسؤولة عن zone (منطقة DNS: جزء من الأسماء تديره جهة وتنشر سجلاته) |

قد يعيد الاسم أكثر من IP لتوزيع الحمل أو اختيار موقع قريب. DNS يجد وجهة محتملة؛ لا يحمل HTML (Hypertext Markup Language؛ لغة وصف بنية الصفحة وعناصرها) ولا يشغّل PHP (اسم لغة برمجة تستخدم كثيرًا لمعالجة طلبات الويب على الخادم).

## رحلة الاستعلام عند غياب الـcache

1. يفحص المتصفح إجاباته المخزنة.
2. يفحص نظام التشغيل ملف hosts والـOS cache (نسخة محفوظة لتقليل تكرار القراءة أو الحساب).
3. يسأل **recursive resolver (خادم DNS ينفذ البحث عن الإجابة بالنيابة عن جهازك)** يوفره الـISP (Internet Service Provider؛ شركة أو جهة توفر الاتصال بالإنترنت) أو المؤسسة أو خدمة عامة.
4. إن لم يملك الإجابة، يسأل resolver خادم **Root**: من يعرف `.com`؟
5. يرشده Root إلى خوادم **TLD (Top-Level Domain؛ الجزء الأعلى من اسم النطاق، زي com)** الخاصة بـ`.com`.
6. يرشده TLD إلى **authoritative name server (خادم الأسماء المسؤول عن نشر الإجابات المعتمدة لجزء من نظام الأسماء)** المسؤول عن النطاق.
7. يعيد authoritative server (الخادم المسؤول عن بيانات النطاق في هذه المرحلة) السجل النهائي.
8. يعيد resolver الإجابة للعميل ويخزنها حسب TTL (Time To Live؛ عمر النسخة المخزنة في DNS، وفي IPv4 حقل منفصل يحد عدد مرات تمرير الحزمة).

```text
Browser/OS cache
      ↓ cache miss
Recursive resolver
      ↓
Root → TLD → Authoritative
                    ↓
                IP + TTL
```

:::caution[تصحيح مهم]
المتصفح لا يسأل Root وTLD بنفسه عادة، والرحلة الكاملة لا تتكرر لكل طلب. الـrecursive resolver يقوم بها عند غياب إجابة صالحة من الـcache.
:::

## TTL: السرعة مقابل سرعة التغيير

الـTTL عدد ثوانٍ يسمح خلالها بتخزين الإجابة. TTL طويل يقلل الاستعلامات لكنه يجعل تغيير السجل أبطأ في الظهور عند بعض العملاء. TTL قصير يسرّع الانتقال بعد انتهاء القيم المخزنة، لكنه يزيد عدد الاستعلامات.

«انتشار DNS» ليس زرًا ينتظر العالم كله بعده مدة ثابتة. كل cache يحتفظ بالإجابة القديمة حتى تنتهي مدتها، وقد تطبق بعض الأنظمة سياسات إضافية.

## تجربة عملية وقراءة النتيجة

```bash
nslookup -type=A example.com
nslookup -type=AAAA example.com
nslookup -type=MX example.com
```

نتيجة `A` ستكون شبيهة بالآتي، مع اختلاف العنوان والـresolver:

```text
Name:    example.com
Address: 93.184.216.34
```

- `-type=A` يطلب IPv4 تحديدًا.
- `Name` هو الاسم الذي جرى حله.
- `Address` هو أحد العناوين المعادة، وليس ضمانًا بأن خدمة HTTP (Hypertext Transfer Protocol؛ قواعد طلب الموارد والرد عليها في الويب) تعمل.
- طلب `AAAA` قد يعيد IPv6 أو لا يجد سجلًا.
- طلب `MX` يبحث عن خوادم البريد، لا خادم الويب.

## أخطاء شائعة

- اعتبار DNS اتصالًا بالخادم؛ هو خطوة لاكتشاف العنوان.
- افتراض أن `localhost` يعني جهازًا بعيدًا؛ يعني الجهاز الذي ينفذ الأمر.
- تعديل سجل ثم توقع ظهوره فوريًا رغم وجود caches وTTL.
- استخدام IP قديم مباشرة وتجاوز الاسم، ثم كسر TLS (Transport Layer Security؛ قواعد حماية الاتصال بالتشفير والتحقق) أو الاستضافة التي تعتمد على اسم المضيف.
- اعتبار عدم وجود `AAAA` دليلًا على أن `A` لا يعمل؛ النوعان مستقلان.

## تأكد من فهمك

1. من يسأل Root وTLD عادة؟ **الـrecursive resolver عند غياب الإجابة من cache، لا المتصفح مباشرة.**
2. ماذا يحدث عند انتهاء TTL؟ **تصبح الإجابة المخزنة غير صالحة ويحتاج العميل أو resolver إلى استعلام جديد.**
3. هل يعني نجاح DNS أن الموقع سيفتح؟ **لا؛ هو يحدد عنوانًا، وما زالت مراحل الاتصال وTLS وHTTP والتطبيق قائمة.**
