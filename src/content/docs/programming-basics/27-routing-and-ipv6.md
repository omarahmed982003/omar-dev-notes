بعد تحديد هل الوجهة محلية، نحتاج نعرف الجهاز التالي في الطريق. **التوجيه — Routing** اختيار طريق للحزمة من جدول. **Next hop — النقلة التالية** الجهاز الذي نستلمه له الآن. هنبدأ بجدول صغير قبل توسيع العناوين إلى IPv6.


## Routing

تحتوي Routing Table على شبكات وNext Hop وواجهة وربما Metric. يختار Router المسار الأكثر تحديدًا وفق Longest Prefix Match. وإذا لم توجد قاعدة أدق يستخدم Default Route مثل `0.0.0.0/0`.

## IPv6

يستخدم IPv6 عناوين 128 بت مثل `2001:db8::1`. يوفر مساحة هائلة ويستخدم Neighbor Discovery بدل ARP. توجد عناوين Link-local تبدأ غالبًا بـ`fe80::`، وLoopback هو `::1`. لا يعني وجود IPv6 اختفاء الجدران النارية أو الحاجة إلى سياسات وصول واضحة.

## اختيار الطريق وقراءة IPv6

**Prefix — بادئة العنوان** البتات المشتركة التي تحدد الشبكة. **Next hop — النقلة التالية** الجهاز التالي الذي نرسل إليه. **Metric — كلفة مسار** تساعد الاختيار بين مسارات مرشحة وفق النظام والسياسة؛ أطول بادئة مطابقة أسبق من مقارنة الكلفة بين مسارات مختلفة التحديد في جدول توجيه عادي.

**تدريب محلول:** الجدول يحتوي `0.0.0.0/0 → A`، و`192.168.0.0/16 → B`، و`192.168.1.0/24 → C`. الوجهة 192.168.1.70 تختار C، و192.168.2.8 تختار B، و203.0.113.8 تختار A. اخترنا أطول تطابق لا أصغر رقم راوتر.

IPv6 يكتب 128 بتًا عادة في ثماني مجموعات سداسية عشرية، كل منها 16 بتًا. يمكن حذف أصفار بداية المجموعة، و`::` تختصر مجموعات صفرية متتالية مرة واحدة في العنوان. `2001:db8::1` عنوان أمثلة، و`::1` للجهاز نفسه. نطاق العناوين المحلية للوصلة هو `fe80::/10`؛ لا يخرج تلقائيًا للإنترنت.

**SLAAC، Stateless Address Autoconfiguration** تكوين عنوان تلقائي اعتمادًا على معلومات يعلنها الراوتر. **Router Advertisement — إعلان الراوتر** رسالة معلومات الشبكة المحلية؛ تعرّف الأجهزة أيضًا بالراوتر الافتراضي. **DHCPv6** نسخة إعدادات IPv6 من بروتوكول التهيئة، قد تضيف عنوانًا أو إعدادات حسب الشبكة؛ المسار الافتراضي لا يأتي منها بالطريقة المعتادة لـDHCPv4. اكتشاف الجيران NDP (Neighbor Discovery Protocol؛ اكتشاف الجيران والراوترات وإعدادات الوصلة في IPv6) يحل دور معرفة عناوين الوصلة. يبقى **Firewall — جدار ناري** بقواعد سماح ومنع مطلوبًا؛ NAT لا يغني عنه.

## الجهاز محتاج أكتر من IP علشان يتصل

لما تتصل بالـWi-Fi (اتصال لاسلكي بالشبكة المحلية؛ لا يضمن اتصالها بالإنترنت)، جهازك محتاج عنوانه، وحجم الشبكة المحلية، والـDefault Gateway (البوابة الافتراضية: الراوتر الذي نرسل له الوجهات التي لا نملك لها مسارًا أدق)، وDNS (Domain Name System؛ نظام يجيب عن أسئلة أسماء النطاقات، ومنها عناوينها) Resolver. غالبًا DHCP (Dynamic Host Configuration Protocol؛ خدمة تمنح الجهاز إعدادات الشبكة تلقائيًا) بيوفرهم تلقائيًا:

```text
Discover → Offer → Request → Acknowledge
```

الـSubnet Mask أوCIDR (Classless Inter-Domain Routing؛ كتابة طول بداية الشبكة بعد شرطة مائلة) يحدد العناوين المحلية. لو الوجهة Local، الجهاز يتواصل معها على الـLink. لو خارجها، يرسل للـGateway. الراوتر يقرأ جدول Routes ويختار أكثر Prefix تحديدًا يطابق الوجهة.

NAT (Network Address Translation؛ تغيير عناوين IP أثناء مرور الحزم بين شبكات) مش هو Routing. Routing يختار الطريق، أما NAT فيغيّر عناوين أوPorts (منفذ منطقي برقم يميز جهة استقبال في بروتوكول النقل) أثناء المرور. في البيت، PAT (Port Address Translation؛ تمييز اتصالات أجهزة خلف عنوان واحد باستخدام المنافذ) يسمح لأجهزة كثيرة تشارك Public IPv4 (Internet Protocol version 4؛ إصدار عناوين الشبكة ذي32 بتًا) واحدة باستخدام Ports. ده مش بديلًا عن Firewall، ولا يجعل الشبكة آمنة تلقائيًا.

IPv6 (Internet Protocol version 6؛ إصدار عناوين الشبكة ذي128 بتًا) وسّع مساحة العناوين ويستخدم Neighbor Discovery بدل ARP (Address Resolution Protocol؛ سؤال عن عنوان MAC المقابل لعنوان IPv4 على الشبكة المحلية). شكل العنوان اتغير، لكن Prefix وRoute وNext Hop ما زالوا أساس القرار.
