خادم قادر على تنفيذ طلب سليم قد يتعرض لطلبات ضارة أو أكثر من قدرته. هنفرق بين فحص الطلب وتنظيم عدد الطلبات.

## ثلاث طرق للعد بأرقام صغيرة

**Rate limit — حد معدل الطلبات** يقرر كم طلبًا نقبل خلال وقت. لو الحد2 كل10ثوانٍ:

| الطريقة | الفكرة | أثرها |
|---|---|---|
| Fixed window — نافذة ثابتة | عداد يبدأ من جديد كل10ثوانٍ | قد يقبل طلبين آخر نافذة وطلبين أول التالية قريبين جدًا |
| Sliding window — نافذة متحركة | انظر للعشر ثواني السابقة للحظة الحالية | يتجنب نفس القفزة عند الحد، وله أكثر من طريقة تنفيذ |
| Token bucket — مخزن سماح | مخزن سعته2، وكل5ثوانٍ نضيف سماحًا حتى السعة | طلبان فورًا لو ممتلئ، ثم انتظار التجديد؛ كل طلب يستهلك سماحًا |

في [المعمل](/programming-basics/32-local-network-lab/) افتح `/limited` على8766 ثلاث مرات سريعًا:200،200،429. `Retry-After` يقترح زمن انتظار. هذه نافذة ثابتة مشتركة للتجربة، مش سياسة عادلة لكل مستخدم. حماية محتوى الطلب موضوع مختلف عن عدد الطلبات.

## WAF ليس بديلًا لأمان التطبيق

يفحص **Web Application Firewall** خصائص الطلب ويطبق Managed Rules أو قواعد مخصصة ضد أنماط معروفة. يستطيع حظر أو Challenge أو Log، لكنه لا يعرف قواعد المجال كاملة: قد يكون طلب تعديل فاتورة صالح الصياغة لكن غير مسموح لهذا المستخدم. لذلك تظل Validation والمصادقة والصلاحيات وParameterized Queries داخل التطبيق.

اختبر القواعد في وضع مراقبة قبل الحظر إن أمكن؛ القاعدة الواسعة قد تنتج False Positives وتوقف عملاء حقيقيين. وثّق الاستثناءات بمدة ومالك وسبب بدل تعطيل الحماية دائمًا.

## Rate Limiting وإدارة الاندفاع

يمكن حساب الحد حسب IP (Internet Protocol؛ قواعد عنونة الحزم وتوجيهها بين الشبكات، وعنوان IP رقم يحدد واجهة في هذا السياق) أو User ID أو API (Application Programming Interface؛ اتفاق يسمح لبرنامج بطلب بيانات أو عملية من مكوّن آخر) Key أو Tenant أو Route. من النماذج Fixed Window وSliding Window وToken Bucket. يسمح Token Bucket باندفاع قصير حتى سعة الدلو ثم يحد المعدل المستمر.

أعد `429 Too Many Requests`، وأرسل `Retry-After` عندما تستطيع إعطاء قيمة صحيحة. لا تعتمد على IP وحده في كل الحالات؛ قد يشترك آلاف المستخدمين خلف NAT (Network Address Translation؛ تغيير عناوين IP أثناء مرور الحزم بين شبكات)، وقد يبدل المهاجم عناوينه.

فرّق بين Rate Limit لمنع الإساءة، وConcurrency Limit لمنع تشبع Workers (وحدة تنفيذ تتولى مهمة أو طلبًا؛ قد تكون عملية أو خيطًا حسب النظام)، وQuota لاستهلاك خطة خلال يوم أو شهر. عند الضغط الشديد استخدم Backpressure (إبطاء المنتج عندما لا يستطيع المستهلك متابعة معدل البيانات) أو Load Shedding بدل قبول عمل لن يكتمل.
