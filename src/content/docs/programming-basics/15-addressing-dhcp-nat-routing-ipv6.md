جهازك عرف عنوانه، لكن الراوتر إزاي يرجع رد الإنترنت له هو، مش لجهاز تاني في البيت؟ هنقرأ إعدادات جهاز، وبعدها نمشي وراء ترجمة اتصالين.

محتاج تفرق بين IP، عنوان واجهة في الشبكة، و**Port — منفذ** يميز جهة استقبال في بروتوكول النقل. لو المنفذ لسه جديدًا، اقرأ جدول الترجمة كتتبع وارجع له بعد [درس المنافذ](/programming-basics/04-url-ports-http/). مش مطلوب تعديل راوتر أو فتح منفذ.

## اقرأ إعداداتك قبل الحساب

على Windows اكتب `ipconfig /all` في PowerShell. اختَر المحول المتصل واقرأ:

| الحقل | دوره | قيمة تدريب |
|---|---|---|
| IPv4 Address | عنوان واجهة جهازك | 192.168.1.20 |
| Subnet Mask | يحدد جزء الشبكة | 255.255.255.0 |
| Default Gateway | النقلة التالية عند غياب طريق أدق | 192.168.1.1 |
| DNS Servers | خوادم نسألها عن أسماء المواقع | العنوان المعروض عندك |

**Default gateway — بوابة افتراضية** مش خادم DNS بالضرورة، حتى لو نفس الجهاز يؤدي الدورين. القيم أمثلة؛ لا تنسخها في إعداداتك. لو فيه VPN أو عدة محولات، قد ترى أكثر من مسار؛ اقرأ ولا تغيّر.

الحساب التفصيلي في [حدود الشبكة](/programming-basics/26-subnet-calculations/)، واختيار المسار و IPv6 في [درس التوجيه](/programming-basics/27-routing-and-ipv6/).

## DHCP

**DHCP، Dynamic Host Configuration Protocol** بروتوكول يمنح الجهاز إعدادات آليًا لمدة اسمها **Lease — إيجار قابل للتجديد**: عنوانًا وقناعًا وبوابة وخوادم DNS.

في بداية شائعة لجهاز من غير إعداد سابق:

1. **Discover:** يسأل عن خادم إعدادات متاح.
2. **Offer:** خادم يعرض إعدادات وإيجارًا.
3. **Request:** العميل يطلب العرض المختار.
4. **Acknowledgement:** الخادم يؤكد الإعدادات.

التجديد لا يعني تكرار هذا التبادل كله حرفيًا كل مرة. DHCP يجهز الإعدادات؛ لا يضمن أن خادم الويب البعيد يعمل. عنوان العميل قد يتغير، فمش عنوان شخص دائمًا.

## Private IP و Public IP و NAT

**Private IP — عنوان خاص** يُستخدم داخل شبكات خاصة. نطاقات IPv4 الشائعة: `10.0.0.0/8` و`172.16.0.0/12` و`192.168.0.0/16`؛ لا تُوجّه مباشرة كوجهات عامة على الإنترنت.

**Public IP — عنوان عام** قابل للتوجيه عالميًا وفق تخصيصه والمسارات؛ مش ضمان أن عليه خدمة متاحة. **NAT، Network Address Translation** تغيير عناوين أثناء عبور حد شبكة. **PAT، Port Address Translation**، وتسمى أيضًا NAPT، تستخدم المنافذ مع العناوين لتمييز اتصالات خلف عنوان عام واحد.

## جهازان ومنفذ محلي واحد: مين يستقبل الرد؟

تتبع ورقي لاتصالات TCP، مش إعدادًا نطبقه. العنوانان `203.0.113.5` و`198.51.100.10` محجوزان للتوثيق؛ نسمي الأول «العام» داخل النموذج فقط، ولا نتصل بهما.

الجهازان يتصلان بنفس خادم النموذج `198.51.100.10:443`. كلاهما اختار منفذ مصدر 51000، وده لا يخلطهما لأن عنوانيهما مختلفان.

| نقطة الربط | المصدر IP:port |
|---|---|
| أ داخل | 192.168.1.20:51000 |
| أ خارج | 203.0.113.5:40001 |
| ب داخل | 192.168.1.21:51000 |
| ب خارج | 203.0.113.5:40002 |

**جدول الترجمة** يحتفظ بالربط اللازم للعودة. أرقام 40001 و 40002 اختيارات توضيحية، مش قاعدة ثابتة لكل راوتر. التتبع هنا لنفس الوجهة وبروتوكول TCP؛ تفاصيل المطابقة تختلف بين أنواع NAT.

1. أ يخرج؛ الراوتر يبدل **المصدر** الخاص إلى `203.0.113.5:40001`.
2. ب يخرج؛ يستعمل ربطًا آخر `203.0.113.5:40002`.
3. رد موجّه إلى `203.0.113.5:40002` يطابق اتصال ب.
4. الراوتر يعيد كتابة **وجهة الرد** إلى `192.168.1.21:51000`، ثم يمرره داخليًا حسب المسار والسياسة.

خادم الإنترنت في المثال يرى مصدرًا عامًا، وليس العنوان الخاص الأصلي. اختيار الطريق شيء، وتغيير العنوان/المنفذ شيء آخر؛ NAT مش هي Routing.

## حدود الترجمة والاتصالات الواردة

لو ربط انتهى أو ضاع بعد إعادة تشغيل جهاز الترجمة، قد تفشل اتصالات قائمة. وجود IP وحده لا يثبت بقاء حالة الاتصال.

**Port forwarding — تحويل منفذ وارد** قاعدة محددة تربط خدمة خارجية بعنوان ومنفذ داخليين. من غير ربط قائم أو قاعدة مناسبة، مفيش تحويل تلقائي لجهاز داخلي مجهول؛ الطلب قد يخص الراوتر نفسه أو ترفضه السياسة. ما نفتحش تحويلات في التدريب.

**CGNAT، Carrier-Grade NAT** ترجمة إضافية عند مزود الخدمة لعدة مشتركين. قاعدة في راوتر البيت لا تتحكم في طبقة المزود، ولذلك قد لا تكفي لاستقبال اتصال مباشر.

**Firewall — جدار ناري** يقرر السماح والمنع، بينما NAT تترجم. وجود ترجمة لا يثبت أمان الخدمة، ولا يشفر المحتوى، ولا يستبدل قواعد الوصول.

## تمرين مستقل

1. الخادم يرد إلى `203.0.113.5:40001`. اكتب وجهة الرد بعد الترجمة.
2. هل تساوي منفذ المصدر 51000 عند الجهازين يخلط الردود؟ ما المعلومة التي تفرقهما؟
3. الجهاز يملك IP لكن لا يملك Default Gateway ولا مسارًا خارجيًا آخر. ما الذي قد يعمل؟
4. نجح DHCP، لكن موقعًا يعيد HTTP 500. هل إعادة DHCP تصلح الخطأ بالضرورة؟
5. إعداد Port forwarding في البيت مع CGNAT: هل تضمن الوصول من الخارج؟

## تأكد من فهمك

الشبكة المحلية تتحدد بالقناع والمسار، لا بتشابه أول أرقام محفوظة في العنوان. والبوابة و DNS خدمتان مختلفتان، والترجمة والصلاحيات مسؤوليتان مختلفتان.
