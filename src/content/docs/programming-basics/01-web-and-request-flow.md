لما تكتب عنوان موقع وتضغط Enter، الصفحة بتظهر بعد سلسلة خطوات. هنمشي وراء طلب واحد: نعرف عنوان الوجهة، نفتح اتصالًا، نبعت طلبًا، ونفهم الرد. مش مطلوب تكون كتبت برنامج خادم؛ المطلوب تعرف تفتح متصفحًا وتكتب عنوانًا.

## أربع خطوات قبل التفاصيل

تكتب اسم الموقع؛ **DNS** نظام يسأل عن معلومات الاسم ومنها عنوانه. بعدها المتصفح ينشئ اتصالًا بالجهة المناسبة، ويرسل **طلبًا** للصفحة، ويتلقى **ردًا** يعرضه.

```text
Browser ── name question ──> DNS
Browser <─ address answer ── DNS
Browser ── connection + HTTP request ──> Server
Browser <──────── HTTP response ────── Server
```

DNS يجيب عن العنوان؛ محتوى الصفحة لا يمر بداخله. ده أول تصور تحتاجه. أسماء الوسطاء وطرق التشفير تفاصيل تأتي في دروسها. **توقع:** اسم غير موجود يفشل قبل طلب الصفحة؛ عنوان صحيح مع مورد غير موجود يمكن أن يرجع404 من خادم وصلنا إليه.

## الفكرة قبل المصطلحات

تخيّل الإنترنت كشبكة طرق عالمية، والويب كخدمة توصيل تعمل فوق هذه الطرق. الطرق تستطيع حمل أشياء أخرى أيضًا؛ لذلك **الإنترنت ليس هو الويب**:

- **الإنترنت** هو البنية التي تربط الشبكات والأجهزة باستخدام بروتوكولات مثل IP (Internet Protocol؛ قواعد عنونة الحزم وتوجيهها بين الشبكات، وعنوان IP رقم يحدد واجهة في هذا السياق).
- **الويب** خدمة تستخدم هذه البنية للوصول إلى موارد، يعني صفحات أو صور أو بيانات، بعناوين URL (Uniform Resource Locator؛ عنوان يحدد موردًا وطريقة الوصول إليه) عبر HTTP (Hypertext Transfer Protocol؛ قواعد طلب الموارد والرد عليها في الويب) أو HTTPS (Hypertext Transfer Protocol Secure؛ طلبات ويب عبر اتصال محمي بالتشفير والتحقق من هوية الطرف الآخر).
- البريد الإلكتروني، ومكالمات الإنترنت، والألعاب خدمات تستخدم الإنترنت من غير أن تكون صفحات ويب.

هذا الفرق مفيد عند تشخيص الأعطال: نجاح الاتصال بالإنترنت لا يضمن أن موقعًا بعينه أو خدمة HTTP تعمل.

## العميل والخادم: دوران لا نوعان من الأجهزة

الـ**Client** برنامج يبدأ الطلب: متصفح، تطبيق هاتف، أو أداة مثل `curl` ترسل طلبًا وتعرض الرد نصيًا. والـ**Server** برنامج يستقبل الطلب ويعيد استجابة. قد يعمل الاثنان على جهازك أثناء التطوير، وقد تمر الاستجابة في الإنتاج عبر عدة خوادم.

```text
المستخدم → Client → HTTP Request → Server
                                  ↓
                           برنامج الموقع ↔ بياناته
                                  ↓
المستخدم ← عرض الصفحة ← HTTP Response
```

كلمة «خادم» قد تعني الجهاز أو البرنامج حسب السياق. الأدق هنا هو الدور: برنامج ينتظر الطلبات على عنوان ومنفذ؛ المنفذ رقم يحدد جهة الاستقبال داخل الجهاز.

## اقرأ الرابط قبل أن تتبعه

```text
https://shop.example/products/42?currency=EGP#reviews
```

- `https` هو الـscheme (طريقة الوصول في بداية العنوان، مثل https) أو البروتوكول المطلوب.
- `shop.example` هو اسم المضيف الذي يحتاج إلى DNS (Domain Name System؛ نظام يجيب عن أسئلة أسماء النطاقات، ومنها عناوينها).
- `/products/42` هو المسار الذي يرسله المتصفح للخادم.
- `currency=EGP` هي query string (معاملات بعد علامة ? في العنوان، مثل name=Omar) وتصل عادة إلى الخادم.
- `#reviews` هو fragment (جزء بعد # يستخدمه العميل محليًا، مثل موضع عنوان في الصفحة) يستخدمه المتصفح، ولا يُرسل في HTTP Request (طلب: رسالة يرسلها العميل ليطلب موردًا أو عملية) عادة.

## جرّب طلبًا حقيقيًا

```bash
curl.exe -i "https://example.com/"
```

سترى نتيجة شبيهة بالآتي، وقد تختلف بعض الرؤوس:

```text
HTTP/2 200
content-type: text/html

<!doctype html>
...
```

- `curl` هو العميل بدل المتصفح.
- `-i` يطلب إظهار response headers مع الـbody.
- `HTTP/2 200` يعني أن الطلب نجح على مستوى HTTP؛ لا يعني أن كل منطق العمل صحيح.
- `content-type` يخبر العميل كيف يفسر الـbody.
- ما بعد السطر الفارغ هو جسم الاستجابة.

لرؤية خطوات الاتصال بتفصيل أكبر:

```bash
curl.exe -v "https://example.com/" -o NUL
```

استخدم `/dev/null` بدل `NUL` على Linux وmacOS. الخيار `-v` يعرض معلومات الاتصال وTLS والطلب، و`-o` يمنع طباعة جسم الصفحة كي تركز على الرحلة.

## أخطاء شائعة

- **«DNS يفتح الصفحة»:** DNS يعيد عنوانًا؛ HTTP هو الذي يطلب المورد.
- **«Nginx يشغّل PHP بنفسه»:** غالبًا يمرر الطلب إلى PHP-FPM.
- **«ظهور `200` يعني أن كل شيء صحيح»:** قد تكون النتيجة ناقصة أو خاطئة مع status ناجح.
- **«كل زيارة تصل إلى قاعدة البيانات»:** قد تجيب طبقة cache أو ملف ثابت قبل ذلك.
- **«Server يعني جهازًا ضخمًا»:** هو دور يمكن أن يؤديه برنامج صغير على جهازك.

## تأكد من فهمك

1. ما الفرق العملي بين الإنترنت والويب؟
   - **الإجابة:** الإنترنت بنية النقل العامة، والويب خدمة تستخدمها عبر HTTP/HTTPS. لذلك قد يعمل الإنترنت بينما تتعطل خدمة ويب محددة.
2. لماذا يمكن أن يكون جهازك Client وServer في الوقت نفسه؟
   - **الإجابة:** لأنهما دوران برمجيان؛ المتصفح يبدأ الطلب، وخادم التطوير المحلي يستقبله، حتى لو عملا على الجهاز نفسه.
3. أين تبحث إذا نجح DNS وTLS لكن الخادم أعاد `403`؟
   - **الإجابة:** الاتصال وصل إلى HTTP، و`403` يعني أن الخادم فهم الطلب ورفض السماح به. افحص الهوية والصلاحيات وقواعد web server أو WAF.
