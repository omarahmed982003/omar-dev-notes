A reference page answers a precise question quickly: what options exist, what each means, and what constraints apply. It differs from a lesson that builds understanding and a how-to guide that walks through a task.

## What should it contain?

- Precise definitions consistent with the rest of the project.
- Complete options, defaults, and boundaries.
- Short examples without turning the page into a long tutorial.
- Links to lessons for explanation and guides for complete tasks.
- A version or date when facts can change.

## Review a reference page

<details><summary>When is a reference page incomplete?</summary><p>When it documents only the common path and omits defaults, boundary cases, errors, or the version to which the information applies.</p></details>

<details><summary>Should a reference contain a long tutorial?</summary><p>Include enough context to understand an option, then link to a lesson for progressive explanation. A reference should make a specific fact quick to find.</p></details>
