متطلبات فرع Full-stack: نجاح 7 و 11، مع أساس HTML/CSS من 5–6؛ ينفع يبدأ بعد 11. النشر يحتاج 13 أو بيئة محلية، ولا يلزم 20. متطلبات فرع Backend العميق: بوابات 14–18 المرتبطة بالمشكلة المختارة؛19/20 فقط لو المشكلة تحتاج موضوعًا منهما. عند دخول الفرع نسجل المتطلبات الفعلية في Progress.

## فرع Full-stack — اختياري، وبعد الاختيار أساسي لإغلاق الفرع

### 21.2 — TypeScript وإطار واجهة واحد

#### 21.2.a — TypeScript بعد JavaScript

- المتطلب والهدف:7 و 11 و 21.1؛ يفرق JavaScript runtime من type checking ويفسر narrowing و null/undefined و unions و typed API data؛ generics بالقدر المطلوب.
- الشرح: bug في shape البيانات ← type annotation/inference ← compiler error مقابل runtime validation ← module/build tooling؛ TypeScript لا يثبت سلامة JSON خارجي وحده.
- المختبر والنتيجة المتوقعة: نقل API client صغير من JavaScript إلى TypeScript بوضع strict مناسب؛ الأخطاء المعروفة تظهر وقت check والرد الخارجي يُتحقق منه وقت التنفيذ.
- الفشل ودليل النجاح: response تخالف type المعلن؛ لا يغطيها as/any لمجرد إسكات checker. الدليل check +tests لحالات valid/invalid/null وشرح مستقل.

#### 21.2.b — Components و State و Forms

- المتطلب والهدف:21.2.a؛ يختار الطالب framework واحدًا فقط بعد شرح مبرره، ويفهم component boundaries/state/effects/routing دون نسخ recipe.
- الشرح: UI state مقابل server state ← events و derived state ← lifecycle/effect وحدوده ← routing ← controlled forms و validation و loading/error؛ نقرأ توثيق النسخة المختارة.
- المختبر والنتيجة المتوقعة: feature قائمة/تفاصيل/تعديل، مع form و routing و tests لسلوك المستخدم، وفصل client validation عن server authorization.
- الفشل ودليل النجاح: navigation سريع أو effect loop أو إرسال form مرتين؛ يكشف الطالب السبب ويصلحه ويثبت فهم ownership والتزامن باختبار جديد.

### 21.3 — جودة الواجهة من Data Fetching إلى Rendering

#### 21.3.a — Server State و Rendering Modes

- المتطلب والهدف:21.2 و HTTP caching؛ يختار fetching/cache invalidation و CSR/SSR/hydration بما يناسب المنتج، مش مطلوب يبني كل الأنماط إجباريًا.
- الشرح: loading/empty/error ← stale response و cancellation/race ← mutations وتحديث cache ← rendering واختلاف server/client؛ لا cache تسمح بتسريب بيانات مستخدم لآخر.
- المختبر والنتيجة المتوقعة: feature للقراءة والتعديل، مع ردود متأخرة ومستخدمين مختلفين؛ يظهر أحدث اختيار، وتتحدث الواجهة بعد الحفظ، وتفضل البيانات معزولة.
- الفشل ودليل النجاح: response قديمة تغطي أحدث state أو hydration mismatch؛ يفسر الطالب السبب ويصلح العقد ويختبره، مع رسم flow صغير.

#### 21.3.b — Accessibility و Performance و Security

- المتطلب والهدف:21.3.a وأساس 5–7 وأمان الواجهات من 11؛12 مرجع للتعمق لا شرط إنهاء كامل قبل الفرع. يقيّم feature باستخدام keyboard/focus/labels/errors، ويحدد performance budget و browser security حسب الخطر. لو فيه متطلب أمان ناقص نصلحه بمختبر محدد قبل النجاح.
- الشرح: user journey ← semantic markup و focus management ← asset/request budget وقياس ← XSS/CSRF/CORS و safe rendering ← SEO/meta/status حسب حاجة المنتج؛ درجة أداة لوحدها مش كفاية عن الفحص اليدوي.
- المختبر والنتيجة المتوقعة: رحلة كاملة بـ keyboard مع form error و slow network؛ تقرير قياس ببيئة معلنة واختبارات Browser، وقرار Rendering له تبرير.
- الفشل ودليل النجاح: user content غير موثوق أو زر غير قابل للوصول؛ يمنع النجاح لحد إصلاح الأمان والإتاحة الأساسية. الدليل tests ومراجعة يدوية ومقارنة قبل/بعد.

## فرع Backend العميق — بديل اختياري، لا واجهة ثانية

### 21.4 — Case Study متخصصة قابلة للقياس

#### 21.4.a — اختيار مشكلة و Baseline

- المتطلب والهدف:14–18 بحسب المشكلة و 21.1؛ يختار الطالب واحدة: reliable integration، data/query bottleneck، أو reliability recovery. يعلن invariants و SLI و scope.
- الشرح: pain point ← evidence ← فرضية ← alternatives ← خطة تجربة؛ لا عدة frameworks ولا حمل خيالي، ولا متطلب متقدم مش مستخدم.
- المختبر والنتيجة المتوقعة: baseline في مشروع قائم، وبيانات و workload محددان، وثلاث حالات فشل بتمثل المشكلة؛ مش لازم مشروع جديد من الصفر.
- الفشل ودليل النجاح: فرضية ما حسّنتش النتيجة؛ تُرفض بقياس صريح وتتعدل الخطة، مش يتغير معيار النجاح بعد ظهور النتائج.

#### 21.4.b — تحسين ودفاع و Handoff

- المتطلب والهدف:21.4.a؛ ينفذ تحسينًا واحدًا أو حزمة صغيرة مترابطة ويبرر trade-offs، مع correctness و security محفوظين.
- الشرح: implementation محدود ← regression/failure tests ← before/after ← cost/operational burden ← ADR و runbook؛ نرجع لمراجع التخصص حسب الفجوة فقط.
- المختبر والنتيجة المتوقعة: feature أو تحسين عامل ودليل reproduce، ومقارنة metrics ومخاطر التغيير والرجوع.
- الفشل ودليل النجاح: fault جديدة من المقيّم؛ الطالب يشخصها بلا وصفة كاملة ويصلحها أو يعلن حدودها بدليل. تقرير القياس ومحاولة مستقلة شرطان، مش «cases أكتر» بلا عدد أو مخرج.
