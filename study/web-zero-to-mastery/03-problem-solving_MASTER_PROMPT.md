# المرحلة 3 — حل المشكلات وتنظيم البرنامج

الإصدار: 1.1 — 2026-10-21. المتطلبات: بوابة المرحلة 2. نفهم المشكلة ثم نصمم ونختبر؛ مش مسابقة حفظ algorithms. النجاح في كل نقطة 80% مع محاولة مستقلة وخرج قابل للفحص.

### 3.1 — صياغة المشكلة قبل الحل

المتطلبات: 2.9. النتيجة: يحول طلبًا مبهمًا لعقد inputs/outputs/constraints وحالات اختبار.

#### 3.1.a — سؤال وحدود وأمثلة

التسلسل: ما المطلوب؟ ← ما المدخل؟ ← ما المسموح؟ ← ما الناتج؟ ← أمثلة عادية وحدية. المختبر: مواصفات تقرير مصروفات؛ المتوقع اكتشاف سؤال غير محسوم مثل قبول السالب بدل اختراع سياسة صامتة.

#### 3.1.b — Pseudocode و dry run

التسلسل: تقسيم مهام ← pseudocode ← جدول حالة يدوي ← تحويل خطوة واحدة لكود. الغلط: كتابة syntax قبل فهم المطلوب أو اختبار الناتج المتوقع بنفس الخوارزمية الغلط. تمرين مستقل: يصمم تقريرًا جديدًا ويجربه يدويًا قبل التنفيذ؛ الدليل مواصفة وتتبع وكود متوافق.

### 3.2 — البحث والتجميع والعد

المتطلبات: 3.1 و Arrays/functions. النتيجة: يبني loop صحيحة ويشرح ما يظل صحيحًا بعد كل دورة.

#### 3.2.a — مجموع وحد أدنى وأقصى

التسلسل: accumulator ← initial value ← empty input ← min/max ← invariant بسيط. المختبر: مجموع وأكبر مصروف؛ المتوقع معالجة مجموعة فاضية دون اختراع أكبر قيمة صفرية لكل البيانات.

#### 3.2.b — Duplicate و lookup map

التسلسل: مقارنة زوجية أولًا ← map لتذكر ما ظهر ← تمييز قيمة عن عدد مرات ظهورها. الغلط: array key غير موجود يساوي count صفرًا في كل استعمال. تمرين مستقل: يعد المصروفات حسب الفئة ويكتشف تكرار معرف؛ الدليل حالات تكرار/فراغ ومقارنة بحساب يدوي.

### 3.3 — الوقت والذاكرة وتقدير التكلفة

المتطلبات: 3.2؛ وحدات ونسب من 1.2. النتيجة: يفرق قياس وقت تشغيل واحد عن نمو تكلفة الحل مع المدخل.

#### 3.3.a — عد الشغل قبل الرموز

التسلسل: عدد عناصر وعدد مقارنات ← n و n² ← O(n)/O(n²) ← المساحة الإضافية. المختبر: احسب عدد العمليات لبحث خطي ومقارنة زوجية لثلاثة أحجام؛ المتوقع نمو مختلف قابل للتفسير.

#### 3.3.b — Log والقياس و built-ins

التسلسل: تقليل المجال للنصف لتفسير O(log n) ← وظيفة builtin ليست مجانية ← توقيت متكرر وحدود الجهاز. الغلط: Big-O تتنبأ بالميلي ثانية أو كل loop ين يعني n². تمرين مستقل: يبرر اختيار حل ويقارن عدة أحجام ويذكر trade-off ذاكرة/وقت؛ الدليل counts وقياس لا أرقام أداء مضمونة.

### 3.4 — Arrays والنصوص كبيانات عمل

المتطلبات: 3.3 و 2.9.b. النتيجة: يختار بحثًا وترتيبًا ومقارنة تناسب معنى البيانات.

#### 3.4.a — Filtering و sorting

التسلسل: شرط فلترة ← comparator ← keys والقيم بعد العملية ← tie cases. المختبر: ترتيب مصروفات بمبلغ ثم معرف؛ المتوقع ترتيب معلن مع حالة تساوي، دون الخلط بين رقم ونص رقمي.

#### 3.4.b — بحث خطي وثنائي

التسلسل: البحث الخطي ← شرط بيانات مرتبة للثنائي ← حدود low/high ← غياب العنصر. الغلط: binary search تصلح لأي array أو تغيير ترتيب البيانات بلا مراعاة الغرض. تمرين مستقل: ينفذ بحثًا صغيرًا ويبرر اختياره ويفحص أول/آخر/غائب؛ دليل تتبع واختبار. التعمق في trees/graphs في المسار المتخصص لاحقًا.

### 3.5 — الملفات وصيغ البيانات وتنظيم عدة ملفات

المتطلبات: 3.4 و 1.6. النتيجة: يحفظ ويستعيد بيانات ويفصل source إلى ملفات مع معالجة فشل معلنة. نقدم هنا معنى failure return و exception بصورة موضعية قبل أي API محتاجاه؛ التشخيص المتعمق في 3.6.

#### 3.5.a — Read/write و CSV/JSON

التسلسل: path ← open mode ← قراءة/كتابة وإغلاق ← فحص النتيجة ← parse ← validate schema بسيط. المختبر: round trip لثلاثة مصروفات؛ المتوقع نفس البيانات بعد الحفظ والتحميل مع رسالة واضحة لملف مفقود أو JSON تالف، وعدم الكتابة فوق الأصل التالف بلا قرار.

#### 3.5.b — Require و bootstrap آمن

التسلسل: `require/include` وفروقهما ← `_once` وقت الحاجة ← `__DIR__` لمسار ثابت ← ملف دوال/ملف تشغيل/bootstrap صغير ← فشل import. الغلط: current directory دائمًا مكان الملف، أو include لاسم قادم من المستخدم. تمرين مستقل: يفصل parsing والحساب والحفظ ويشغّل البرنامج من مجلد آخر، مع CSV غير صالح وفشل كتابة مُحاكى؛ الدليل ملفات وأوامر ونتيجة، دون اختبارات تلف حقيقية أو concurrent file store إنتاجي.

### 3.6 — الأخطاء والتصحيح والـ exceptions

المتطلبات: 3.5 وفشل API التمهيدي. النتيجة: يعزل السبب بدل إخفاء التحذير ويختار بين رفض مدخل وفشل تشغيلي.

#### 3.6.a — قراءة الدليل

التسلسل: expected/actual ← warning/error/exception ← stack trace ← أقل reproduction ← موضع نشأة السبب. المختبر: parsing يفشل بسبب field ناقص؛ المتوقع تحديد السطر والسبب لا تغيير عشوائي حتى يختفي العرض.

#### 3.6.b — أدوات وتصرف آمن

التسلسل: breakpoint و step/watch إذا توفر debugger ← logging بلا أسرار ← try/catch/finally وإعادة رمي مناسبة ← validation مقابل crash. الغلط: catch فارغ أو `@` علاج عام أو عرض trace للمستخدم. تمرين مستقل: يصلح عطلًا جديدًا ويضيف log مفيدًا ويثبت النجاح والفشل المتوقع؛ دليل reproduction قبل/بعد وشرح لا تخمين.

### 3.7 — اختبار صغير يحمي التصحيح

المتطلبات: 3.6 و functions بلا side effects غير لازمة. النتيجة: يكتب اختبارات تكشف regression بدل مجرد تشغيل البرنامج يدويًا.

#### 3.7.a — Case و expected و actual

التسلسل: اختبار ناجح وفاشل عمدًا ← assertion ← حالة حدود ← independent expected value. المختبر: test runner بسيط لدالة جمع/تحقق؛ المتوقع exit code فشل عند كسر الدالة ونجاح بعد الإصلاح. لا نعتمد على PHP assertions وحدها لو إعداد runtime يعطلها؛ نوضح إعداد المختبر أو مقارنة تفشل صراحة.

#### 3.7.b — عزل الملفات و regression

التسلسل: temp fixtures داخل التدريب ← setup/cleanup محدود ← regression test ← فصل unit عن integration تمهيديًا. الغلط: اختبار يغير ملفات الطالب الحقيقية أو expected ينتج من نفس الدالة المختبرة. تمرين مستقل: يضيف test لعطل 3.6 ويثبت أنه يفشل قبل الإصلاح ثم ينجح بعده؛ الدليل أوامر وخرج وحالات غير صالحة.

### 3.8 — جسر Git المحلي لحماية شغل التدريب

المتطلبات: 3.7. النتيجة: يحفظ تغيرًا معلومًا ويسترجعه بأمان ويفسر ما يتغير قبل أي أمر.

#### 3.8.a — مختبر حفظ ومراجعة محلي

التسلسل: معنى version control ← repository تجريبي ← working tree/staging/commit كنموذج صغير ← status/diff ← snapshot بعد موافقة تنفيذ التدريب. [Git Master](../Git_Master_Prompt.md) و[تقدمه](../GIT_PROGRESS.md) مرجعان لحدود المسار القديم، لا شرط إكمال عشرات نقاطه هنا. المختبر محلي بملفات وهمية؛ المتوقع تفسير diff وما يدخل snapshot وما لا يدخله. تمرين مستقل: يراجع تغييرين ويحدد ما ينوي حفظه وما يستبعده، مع دليل وتقييم محلي 80%.

#### 3.8.b — بوابة دمج بلا درجات مكررة

التسلسل: خطأ في نسخة التدريب ← قراءة status/diff ← استرجاع مستهدف معلوم المصدر والأثر بعد حفظ أي شغل مطلوب ← تحقق. الغلط: إنشاء commit يعني انتهاء Git أو أمر محو واسع حل افتراضي لاسترجاع سطر. تمرين مستقل: يعالج تغييرًا خاطئًا ويتوقع الأثر قبل التنفيذ؛ دليل قبل/بعد و 80%. الدرجات هنا للجسر المحلي فقط؛ لا تغيير `GIT_PROGRESS.md` أو إعفاء نقاطه، ولا commit/push في مشروع المستخدم دون إذن، ولا نشر Git المؤرشف. المنهج القديم يُدرس لاحقًا صراحة بترتيبه إن اختير؛ `3.8` ليست تصريحًا بكتابة خارجية.

## مشروع المرحلة وبوابة الخروج

نسخة المصروفات تحفظ JSON/CSV، source متعدد الملفات، معالجة ملف غير صالح وفشل كتابة، واختبارات مستقلة قابلة للتشغيل. البوابة: feature وتصحيح عطل جديد، دليل Git تجريبي، و 80% لكل checkpoint والمشروع. Algorithms المتخصص يبدأ بعد هذه المرحلة بجرعات عند الحاجة؛ إنهاؤه كله ليس شرطًا لأول ويب. راجع [PHP include](https://www.php.net/manual/en/function.include.php) و[require](https://www.php.net/manual/en/function.require.php) عند التطبيق.

## تشغيل جلسة هذه الجزئية

- اقرأ [الفهرس](README.md) و[قواعد التدريس والتقييم](COMMON_RULES.md) كاملين، ثم هذا الملف و[ملف التقدم](03-problem-solving_PROGRESS.md) كاملين قبل الشرح.
- هذا الملف منهج الجزئية، وليس الدرس المنشور أو دليل اجتيازها. اشرح checkpoint واحدة على أجزاء، وسؤالًا واحدًا كل مرة، بالعامية المصرية و PHP افتراضيًا إلا في موضوع لغة أخرى.
- ملف التقدم المجاور يملك الموضع والنتائج الخاصة بهذه الجزئية. الفهرس وملف التوجيه العام لا يكرران الدرجات.
- الجسور التمهيدية المحلية تُدرس وتُقيّم هنا. المرجع القديم لا يفرض إكمال مساره ولا يغير تقدمه؛ عند اختيار دراسة مسار قديم صراحة اقرأ Master و Progress الخاصين به كاملين من study الأب، وسجل درجاته هناك وحده مع مرجع عودة هنا.
- قواعد المنهج المشتركة وخرائط ملاك الموضوعات في COMMON_RULES.md؛ أسماء ملفات المسارات القديمة المذكورة أعلاه تُحل من study الأب، لا من هذا المجلد.
