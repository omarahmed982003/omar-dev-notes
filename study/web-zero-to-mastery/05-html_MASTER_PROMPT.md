# المرحلة 5 — HTML وبناء واجهة لها معنى

الإصدار: 1.1 — 2026-10-21. المتطلبات: بوابة `4.Foundation->HTML` من المرحلة 4، وليس اجتياز تعميق الشبكات كله. نكتب HTML حقيقيًا في ملف ونفحصه في browser؛ design هنا فهم هدف المستخدم وتنظيم المعلومات قبل الزينة.

### 5.1 — المتصفح والوثيقة وهيكل الصفحة

المتطلبات: بوابة الشبكات الأساسية و 1.6. النتيجة: ينشئ صفحة عربية صحيحة البنية ويفرق source عن DOM الناتج.

#### 5.1.a — من ملف لصفحة

التسلسل: element/tag/attribute ← nesting ← doctype/html/head/body ← فتح ملف أو خادم محلي سبق تجهيزه. المختبر: صفحة عنوان وفقرة ورابط؛ المتوقع ظهورها وتحديد العنصر في DevTools. الغلط: المتصفح صححها إذًا source صحيح دائمًا. تمرين مستقل: يصلح nesting معطوبًا ويتحقق بأداة فحص مناسبة؛ الدليل source والفرق في DOM.

#### 5.1.b — Metadata ولغة واتجاه

التسلسل: HTML parsing و DOM ← charset/title/viewport ← `lang` و`dir` ← تحميل CSS/JS كمراجع موارد دون تدريس لغاتهما الآن. المختبر: صفحة عربية بها مصطلح إنجليزي؛ المتوقع عنوان tab واضح ونص غير مشوه واتجاه مناسب. تمرين مستقل: نسخة إنجليزية LTR لنفس البنية ويعلل metadata؛ دليل و 80% لكل جزئيتي النقطة.

### 5.2 — Semantic HTML وتنظيم المحتوى

المتطلبات: 5.1. النتيجة: يختار العنصر حسب المعنى وينظم صفحة يفهمها المستخدم، لا حسب شكل افتراضي فقط.

#### 5.2.a — هيكل يخدم مهمة

التسلسل: من المستخدم وماذا يريد؟ ← content outline ← headings/landmarks ← lists ← link مقابل button. المختبر: مخطط كتالوج على ورق ثم HTML؛ المتوقع مسار واضح من قائمة لتفاصيل، دون div لكل شيء أو heading لحجم الخط فقط.

#### 5.2.b — بيانات وروابط قابلة للفهم

التسلسل: جدول بيانات مع headers/caption ← نص رابط معبر ← navigation و current page ← فصل المحتوى عن الشكل. الغلط: table لتخطيط الصفحة أو «اضغط هنا» لكل الروابط. تمرين مستقل: يبني مقارنة منتجات ويبرر العناصر وترتيب المعلومات؛ دليل DOM ومخطط رحلة و 80%، لا يلزم رسم واجهة احترافي.

### 5.3 — Forms تجمع بيانات ذات معنى

المتطلبات: 5.2 و HTTP الأساسي 4.7.a. النتيجة: يبني نموذجًا مسمى ويرى البيانات التي سيُرسلها دون ادعاء حمايتها من العميل.

#### 5.3.a — حقول وأسماء وتسميات

التسلسل: form/action/method ← label/name/value ← input types/select/textarea/button ← grouping وتعليمات. المختبر: نموذج طلب من ثلاثة حقول؛ المتوقع ربط كل label بحقل وقراءة keys في طلب اختبار محلي. الغلط: placeholder بديل label أو id يُرسل بدل name.

#### 5.3.b — Validation وتجربة إرسال

التسلسل: required/limits ← رسالة مساعدة ← GET مقابل POST ← multipart ورفع الملف كمفهوم ← تعطيل validation يوضح حدوده. المختبر: إرسال صالح وغير صالح لخادم mock محلي، بلا بيانات حساسة؛ المتوقع شرح query/body، لا تخزين فعلي. تمرين مستقل: يحسن نموذجًا غامضًا ويعرض ماذا يُرسل وماذا لا يُرسل؛ 80% ودليل، والتحقق الخادمي في 8.3.

### 5.4 — Accessibility من أول واجهة

المتطلبات: 5.3. النتيجة: ينجز رحلة أساسية بلوحة المفاتيح ويشرح الاسم القابل للوصول ورسالة الخطأ.

#### 5.4.a — Keyboard و focus والاسم

التسلسل: semantic controls ← tab order طبيعي ← visible focus ← accessible names ← لا positive tabindex كحل عام. المختبر: تصفح الكتالوج والنموذج دون mouse؛ المتوقع الوصول لكل action والتعرف على هدفه. الغلط: click يعمل إذًا المكون accessible.

#### 5.4.b — Alt وأخطاء النماذج و ARIA

التسلسل: صورة محتوى مقابل decorative ← alt مناسب ← ربط error بالحقل ← تجربة accessibility tree أو screen reader عند توفره ← ARIA عند الحاجة لا لاستبدال element مناسب. تمرين مستقل: يصلح ثلاث عوائق موثقة ويعيد نفس الرحلة؛ دليل قبل/بعد و 80%. لا يدعي توافقًا شاملًا مع معيار من فحص آلي واحد.

### 5.5 — الوسائط والموارد والروابط

المتطلبات: 5.4 و 1.2 و 1.6. النتيجة: يحمل موردًا بحجم مناسب ويشخص رابطًا مكسورًا ويتعامل مع استخدام المحتوى بمسؤولية.

#### 5.5.a — عنوان المورد ودورة تحميله

التسلسل: relative/absolute URL ← linking بين صفحات ← image و width/height ← alt ← network panel. المختبر: صفحة وتفاصيل وصورة محلية؛ المتوقع عدم وجود 404 للموارد بعد نقل المشروع كاملًا لمجلد تدريب آخر. الغلط: مسار قرص الطالب رابط يصلح على جهاز الجميع.

#### 5.5.b — Responsive images ووسائط مفيدة

التسلسل: أبعاد المصدر مقابل العرض ← srcset/sizes بصورة محدودة ← audio/video و captions/transcript عند الاستخدام ← مصدر/ترخيص المحتوى. المختبر: اختيار صورتين مباحتين الحجم لعرضين؛ المتوقع تحميل وشرح اختيار مناسب دون نسخ صور مجهولة الحقوق. تمرين مستقل: يصلح صورة ضخمة ورابطًا مكسورًا ويقدم بديلًا نصيًا؛ دليل requests و 80%.

## مشروع المرحلة وبوابة الخروج

صفحات كتالوج وتفاصيل ونموذج طلب: هدف مستخدم، content outline، semantic structure، لغة واتجاه، تنقل keyboard، موارد محلية وأخطاء نموذج مفهومة. البوابة: 80% لكل checkpoint والمشروع، تنفيذ رحلة مستقلة وتصحيح عائق جديد. لا backend وهمي يُسجل مكتملًا ولا تبدأ CSS قبل صحة البنية. راجع [MDN Learn HTML](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content) عند تجهيز الدروس، لا تنقل قائمة مصطلحات مكان الممارسة.
