# المرحلة 1 — الكمبيوتر بالقدر اللي يأسس مبرمج

الإصدار: 1.1 — 2026-10-21. المتطلبات: بوابة المرحلة 0. مقدمة الهاردوير مختصرة؛ الهدف فهم السوفتوير وتنفيذ برنامج، مش تجميع كمبيوتر أو حفظ مواصفات.

### 1.1 — صورة الجهاز وقت تشغيل برنامج

المتطلبات: 0.3 و 0.5. النتيجة: يتتبع انتقال ملف من التخزين إلى برنامج عامل ويفرق CPU و RAM والتخزين و I/O.

#### 1.1.a — مكونات لها أدوار مختلفة

التسلسل: ملف محفوظ ← تحميل للذاكرة ← تنفيذ تعليمات ← إدخال/إخراج؛ ثم GPU كمعالج مناسب لأنواع شغل متوازٍ، لا بديل عام للـ CPU. المختبر: افتح محررًا وملفًا وراقب الذاكرة و CPU؛ المتوقع تغير قابل للملاحظة، مش رقم أداء ثابت.

#### 1.1.b — تفسير البطء بدل شراء عشوائي

الغلط: RAM تخزين دائم، أو GHz وحده يحدد السرعة. تمرين مستقل: يشرح لماذا ملف موجود بعد إغلاق المحرر، ولماذا قرص أسرع لا يصلح كل بطء CPU؛ الدليل خريطة أدوار وملاحظتان من الجهاز و 80% على الأقل.

### 1.2 — تمثيل البيانات وحجمها

المتطلبات: 1.1. النتيجة: يفرق القيمة عن تمثيلها ويقرأ وحدات و encoding وملف وسائط عمليًا.

#### 1.2.a — من bit إلى نص عربي

التسلسل: bit/byte ← binary/hex بتمثيل قيم صغيرة ← وحدات حجم ومعدلات ← Unicode مقابل UTF-8. المختبر: احفظ نصًا لاتينيًا وآخر عربيًا وافحص الحجم؛ المتوقع ألا نستنتج عدد الأحرف من البايتات دائمًا، مع ضبط إصدار الأداة وطريقة الحفظ.

#### 1.2.b — صورة وصوت وفيديو من بيانات

التسلسل: pixels/channels ← sample rate/bit depth ← frames/codec/container ← lossless/lossy. الغلط: الامتداد وحده يضمن المحتوى أو الضغط مجاني بلا trade-off. تمرين مستقل: يقارن ملفين مباحين ويشرح أثر الدقة/المدة/الضغط، مع حساب حجم تقريبي بسيط ووحدات صحيحة؛ الدليل تقرير و 80%، لا مقرر حسابات منفصل.

### 1.3 — السوفتوير وتنفيذ التعليمات

المتطلبات: 1.1؛ تذكير بمعنى البيانات من 1.2. النتيجة: يميز source و program و runtime ومكتبة و framework و OS من مثال واحد.

#### 1.3.a — من source لبرنامج عامل

التسلسل: تعليمات بشرية الصياغة ← ترجمة/تفسير ومراحل تنفيذ ← runtime ← عملية. المختبر: تتبع مخطط جاهز لملف PHP ثم برنامج مُترجم؛ المتوقع تحديد من يقرأ الملف ومن ينفذ، دون كتابة كود لم يُدرّس.

#### 1.3.b — أدوات لا أسماء للحفظ

التسلسل: برنامج يستعمل مكتبة؛ framework يدير جزءًا من التدفق؛ OS يوفر موارد. الغلط: كل interpreted language لا تترجم أبدًا أو كل source ملف executable. تمرين مستقل: يصنف عناصر سيناريو ويب ويعلل الحدود؛ الدليل تفسير سببي و 80%، ونعيد التجربة بكود فعلي في 2.1.

### 1.4 — نظام التشغيل والعزل

المتطلبات: 1.3. النتيجة: يفهم لماذا التطبيقات لا تملك الجهاز كله وكيف تتقاسم الموارد وتطلب خدمات OS.

#### 1.4.a — Process و thread و scheduling

التسلسل: program مقابل process ← هوية PID ← thread كتدفق تنفيذ ← وقت CPU والانتظار. المختبر: شغّل نافذتين من تطبيق آمن وراقب عملياته؛ المتوقع معرفات وموارد يفسرها الطالب دون افتراض تطابق نافذة واحدة مع process واحدة.

#### 1.4.b — User/kernel والصلاحيات

التسلسل: عملية تطلب قراءة ملف ← system call ← فحص صلاحية ← نجاح/رفض. الغلط: البرنامج البطيء دائمًا يستهلك CPU، أو administrator علاج لكل رفض. تمرين مستقل: يقرأ خرج موارد/خطأ صلاحية تجريبي ويحدد دور التطبيق و OS؛ دليل ملاحظة وشرح و 80%، دون تغيير صلاحيات الجهاز.

### 1.5 — الذاكرة وعمر البيانات

المتطلبات: 1.4 و 1.2. النتيجة: يفرق مساحة عناوين العملية عن RAM الفعلية، ويفسر عمر البيانات والضغط على الذاكرة بمستوى تأسيسي.

#### 1.5.a — عناوين وعمر وتخصيص

التسلسل: address كتجريد ← virtual memory وعزل العمليات ← allocation والعمر ← stack/heap كنموذج عام لا خريطة PHP حرفية. المختبر: رسم ذاكرة لعمليتين ومتابعة فتح/إغلاق تطبيق؛ المتوقع فصل هوية البيانات عن مكانها الفيزيائي.

#### 1.5.b — Buffer و cache وحدود الموارد

التسلسل: تجميع مؤقت مقابل إعادة استعمال ← swap ← memory pressure ← out-of-memory. الغلط: cache مصدر حقيقة أو swap يساوي RAM بلا تكلفة. تمرين مستقل: تفسير حالتي زيادة الذاكرة والانتظار دون استهلاك كل موارد الجهاز؛ دليل رسم وملاحظات و 80%. تفاصيل zval/GC/OPcache مؤجلة لمرحلة 15، لا شرط لأول كود.

### 1.6 — الملفات والتخزين ودلالة الحفظ

المتطلبات: 1.5 و 0.3. النتيجة: يصل لملف بمسار صحيح ويشرح الفرق بين اسم وصيغة وملف مفتوح وكتابة متينة.

#### 1.6.a — المسار والهوية والوصول

التسلسل: directory/path ← relative/absolute ← extension مقابل format ← permissions ← handle/file descriptor. المختبر: افتح نفس الملف من مسارين نسبي ومطلق داخل التدريب؛ المتوقع نفس المحتوى، مع تفسير اعتماد النسبي على موضع البداية.

#### 1.6.b — من write إلى التخزين

التسلسل: application buffer ← OS cache ← device؛ الإغلاق والمزامنة لهما ضمانات مختلفة. الغلط: ظهور رسالة Saved وحده يثبت النجاة من كل انقطاع كهرباء. تمرين مستقل: يشرح سيناريو فشل كتابة ويوثق نسخة اختبار دون تعريض ملفات حقيقية للتلف؛ دليل مخطط وحدود معقولة و 80%. كتابة PHP الفعلية في 3.5.

### 1.7 — Terminal و shell وبيئة البرنامج

المتطلبات: 1.6 و 0.3. النتيجة: يشغّل أمرًا معروفًا من مكان صحيح ويشرح المدخلات والخرج والبيئة.

#### 1.7.a — مكان وأمر و arguments

التسلسل: terminal مقابل shell ← current directory ← quoting للمسارات ذات المسافات ← command و arguments. المختبر: عرض ملفات مجلد تدريب وتغيير موضع العمل ثم الرجوع؛ المتوقع تغير معنى المسار النسبي، لا تغير الملف نفسه.

#### 1.7.b — Environment و PATH وقنوات الخرج

التسلسل: متغير بيئة غير سري ← PATH واختيار executable ← stdout/stderr ← exit code؛ اشرح فرق PowerShell و Bash عند اختلاف الأمر. الغلط: نسخ أوامر منصة أخرى أو عرض كل environment بما فيه أسرار. تمرين مستقل: يشخص أمرًا غير موجود ومسارًا خاطئًا، ويسجل خرجًا ورمز خروج وتفسيرًا؛ نجاح 80%، بلا حذف أو تعديل PATH دائم.

## مشروع المرحلة وبوابة الخروج

تقرير تجريبي يراقب تشغيل برنامج وموارده وملفاته: مخطط أدوار، ملاحظات CPU/RAM، مسار ملف، مثال environment غير سري، وفشل وصول أو أمر. يفسر أين ينتهي دور التطبيق ويبدأ OS ويعيد ملاحظة واحدة مستقلًا. كل checkpoint والمشروع 80% بأدلة؛ لا نطلب كودًا لم يتعلمه الطالب ولا نحول تفاصيل الذاكرة المتقدمة لشرط بداية.
