الإصدار: 1.1 — 2026-10-21. المتطلبات: بوابة المراحل 1–3. كل بروتوكول له درس مالك واحد؛ تأسيسه وتعميقه قسمان في نفس الدرس، مش صفحات مشتتة. لا HTML سابق مطلوب.

## مسار التأسيس والعودة للتعميق

المرور الأول: `4.1.a → 4.2.a → 4.3.a → 4.4.a → 4.5.a → 4.6.a → 4.7.a → 4.8.a → 4.9.a`. بوابة `4.Foundation->HTML` لدخول المرحلة 5 هي نجاح هذه الأجزاء التأسيسية والمختبر الجامع بدرجة 80% لكل منها، لا إنهاء congestion control و MTU وكل التفاصيل أولًا.

### 4.1 — Internet و Web والطبقات

المتطلبات: 1.3 و 3.5. النتيجة: يفرق الشبكة عن خدمة الويب ويتتبع عميلًا وخادمًا وطبقات بيانات.

#### 4.1.a — طلب لخدمة

التسلسل: جهازان ورسالة ← Internet مقابل Web ← client/server ← إطار TCP/IP مبسط ← encapsulation. المختبر: رسم طلب ملف ورده عبر طبقات؛ المتوقع فصل application data عن IP packet، لا حفظ أسماء فقط. تمرين مستقل: يحدد ما يتغير عند استبدال المتصفح بعميل CLI؛ الدليل رسم وتفسير و 80%.

#### 4.1.b — حدود مسؤولية كل طبقة

المتطلبات: الأجزاء التأسيسية كلها. التعمق: headers/payload على امتداد hop وحدود إطار الشبكة المحلية؛ لا مساواة packet بـ request. المختبر: قراءة capture محلي مجهز أو خرج مبسط دون بيانات أشخاص؛ المتوقع ربط طبقات لا تخمين سر تشفير. الغلط: كل طبقة تمنع كل أنواع الفشل. تمرين مستقل: يعزل طبقة خطأ من أدلة ويبررها؛ 80%.

### 4.2 — IP و routing والشبكة المحلية

المتطلبات: 4.1.a. النتيجة: يفسر كيف نصل لعنوان محلي أو بعيد ودور gateway دون ضبط شبكة المستخدم عشوائيًا.

#### 4.2.a — عنوان وطريق

التسلسل: IP مقابل اسم ← IPv4/IPv6 ← subnet كحد شبكة ← gateway و routing ← loopback. المختبر: قراءة إعدادات عنوان ومسار افتراضي بأوامر النظام المناسبة؛ المتوقع تفسير عنوان محلي ووجهة لا الوصول لسيرفر خارجي بعينه. تمرين مستقل: يختار طريق اتصال من مثالين؛ دليل خرج منقح و 80%.

#### 4.2.b — NAT و ARP و DHCP

المتطلبات: 4.4.a و 4.5.a. التعمق: prefix عملي صغير ← جدول routes ← NAT وحدوده ← ARP داخل IPv4 و neighbor discovery في IPv6 ← DHCP لتجهيز الإعدادات. الغلط: NAT تشفير، أو ARP يعثر على MAC لسيرفر بعيد. المختبر: تتبع سيناريو داخل شبكة تدريب مرسوم؛ المتوقع فصل عنوان الخدمة عن next hop. تمرين مستقل: يفسر فشل gateway مقابل DHCP ويقترح فحصًا لا تغيير إعدادات جهاز حقيقي؛ 80%.

### 4.3 — DNS من الاسم للإجابة

المتطلبات: 4.2.a. النتيجة: يفسر resolution والـ cache ويشخص اسمًا خاطئًا دون الخلط بينه وبين تعطل HTTP.

#### 4.3.a — من يسأل مين؟

التسلسل: اسم ← cache محلي ← resolver ← root/TLD/authoritative حسب الحاجة ← A/AAAA/CNAME. المختبر: استعلام لاسم اختبار ومقارنة الإجابة بعنوان؛ المتوقع تمييز resolver عن authoritative. الغلط: كل زيارة تتصل بكل خوادم DNS. تمرين مستقل: يرسم مسار أول طلب وطلب cached؛ دليل و 80%.

#### 4.3.b — TTL وتشخيص وحماية

المتطلبات: 4.6.a و 4.8.a. التعمق: records ملائمة ← TTL/negative cache ← NXDOMAIN مقابل timeout ← propagation كأثر caches ← DNSSEC/DoH وحدود كل حماية. المختبر: مقارنة ردين مجهزين لـ TTL واسم غير موجود؛ المتوقع عدم الادعاء أن DNS يثبت أمان الموقع. تمرين مستقل: خطة فحص لاسم قديم دون نشر أو تعديل DNS عام؛ 80%.

### 4.4 — Ports و sockets وهوية الاتصال

المتطلبات: 4.2.a و process من 1.4. النتيجة: يميز عنوان خدمة عن process وعن اتصال فعلي.

#### 4.4.a — خدمة تستمع واتصال يصل

التسلسل: IP:port ← socket ← listen/accept كتفسير ← loopback ← اتصال مرفوض مقابل timeout. المختبر: خادم تدريب محلي محدود وعميل؛ المتوقع نجاح عنوان ومنفذ معلومين وفشل منفذ غير مستمع. تمرين مستقل: يشخص الخلل ويشرح الأدلة دون فتح firewall؛ 80%.

#### 4.4.b — أكثر من اتصال وعمر socket

المتطلبات: 4.5.a و 4.6.a. التعمق: endpoints وهوية تدفق TCP ← ephemeral ports ← TCP/UDP namespace ← lifecycle وموارد. الغلط: port ثابت يخص process واحدة للأبد أو range يتجاوز 65535. المختبر: قراءة جدول اتصالات محلي منقح؛ المتوقع تمييز listener من established. تمرين مستقل: يشرح عدة عملاء لنفس الخدمة ويقترح فحص address-in-use؛ 80%.

### 4.5 — TCP من فتح الاتصال لإغلاقه

المتطلبات: 4.4.a. النتيجة: يفهم byte stream وحدود الضمان ويبرر framing وفشل الاتصال.

#### 4.5.a — Stream و handshake و framing

التسلسل: اتصال ← handshake ← bytes لا messages ← read/write جزئيان ← newline أو length framing ← close. المختبر: عميل وخادم PHP في التدريب يرسلان رسالة محددة الإطار؛ المتوقع نفس الرسالة مع عدم افتراض أن read واحدة تساوي رسالة. الغلط: TCP يضمن نجاح العملية التجارية. تمرين مستقل: يفسر stream مقسمًا بطريقتين ويعالج إطارًا ناقصًا؛ دليل trace وكود صغير و 80%.

#### 4.5.b — Reliability والتدفق والإغلاق والتشخيص

المتطلبات: 4.9.a واختبارات 3.7. التعمق داخل نفس الدرس: seq/ACK للبايتات ← retransmission ← receiver window مقابل cwnd/congestion ← head-of-line blocking ← FIN/RST/half-close/TIME_WAIT ← keepalive مقابل HTTP reuse. المختبر: تحليل trace مجهز لفقد و ACK وتوقف؛ المتوقع تفسير الترتيب وحدود timeout دون fixed doubling وهمي. تمرين مستقل: يشخص فشل إرسال/رد مجهول ويمنع إعادة عملية تجارية بلا idempotency؛ 80%.

### 4.6 — UDP وحدود datagrams

المتطلبات: 4.5.a. النتيجة: يميز الرسالة عن stream ويعرف الضمانات التي يتحملها التطبيق.

#### 4.6.a — Datagram ومسؤولية التطبيق

التسلسل: رسالة مستقلة ← حدود read ← فقد/تكرار/ترتيب ← مثال استعمال DNS أو real-time. المختبر: بيانات مرقمة مجهزة فيها فجوة وتكرار؛ المتوقع اكتشافهما دون افتراض تسليم مضمون. الغلط: UDP دائمًا أسرع أو لا يستعمله بروتوكول موثوق. تمرين مستقل: يختار النقل لسيناريو مع تبرير وما يحتاجه التطبيق؛ 80%.

#### 4.6.b — MTU والحجم والأمان

المتطلبات: 4.5.b و 4.2.b. التعمق: MTU/MSS ليسا نفس الشيء ← fragmentation و IPv4/IPv6 ← PMTUD ← DNS و QUIC كأمثلة مسؤوليات أعلى ← spoofing/amplification. المختبر: أحجام مضبوطة و trace مجهز؛ المتوقع تفسير small-works/large-fails دون تغيير MTU اعتباطيًا. تمرين مستقل: يكتب خطة تشخيص وقيود حجم آمنة؛ 80%، بلا إرسال مكثف أو اختبار على شبكة عامة.

### 4.7 — HTTP وعقد الطلب والرد

المتطلبات: 4.5.a و 4.6.a. النتيجة: يقرأ request/response حقيقيين ويفسر method/status/headers/body.

#### 4.7.a — URL ورسالة ومعنى

التسلسل: URL وأجزاؤه و encoding ← request/response ← GET/POST و PUT/PATCH/DELETE ← status families ← headers/body ← stateless. المختبر: `curl` و DevTools لمختبر محلي؛ المتوقع شرح 200 و 404 و redirect وفصل GET عن نموذج الجسم. الغلط: stateless يعني TCP جديدة لكل طلب أو UPDATE method قياسية. تمرين مستقل: ينتج طلبًا ويحدد خطأ method أو URL؛ 80%.

#### 4.7.b — Semantics و caching والنسخ

المتطلبات: تطبيق المرحلة 8 أو فهم نماذجه محليًا. التعمق: safe/idempotent ← content negotiation ← content type/length ← cache freshness/validation و ETag ← redirects ← HTTP/1.x مقابل HTTP/2 و HTTP/3. المختبر: رد cached ثم conditional request؛ المتوقع تفسير 304 دون اعتباره body جديدًا. تمرين مستقل: يختار cache policy لبيانات عامة وخاصة ويبرر منع التسريب؛ 80%، auth له مالكه في 8 و 12.

### 4.8 — TLS والثقة وحدود HTTPS

المتطلبات: 4.7.a و 4.3.a. النتيجة: يفصل التشفير عن إثبات الهوية وعن أمان التطبيق.

#### 4.8.a — اسم وشهادة وقناة محمية

التسلسل: تهديد المراقبة/التلاعب ← شهادة و hostname و CA ← handshake واتفاق مفاتيح ← confidentiality/integrity. المختبر: فحص شهادة صالحة وأخرى منتهية من بيانات معدة؛ المتوقع سبب قبول/رفض واضح. الغلط: HTTPS يعني موقعًا موثوقًا في كل تصرفاته. تمرين مستقل: يشرح لماذا لا نعالج خطأ الشهادة بتعطيل التحقق؛ 80%.

#### 4.8.b — Handshake والتجديد وحدود الحماية

المتطلبات: 4.5.b. التعمق: TLS الحديث و ephemeral key agreement ← certificate chain/SNI ← expiry/rotation ← termination عند proxy وحد الثقة ← resumption بمستوى قرار. المختبر: trace أو خرج فحص مُنقح؛ المتوقع عدم تقديم RSA التاريخي كنموذج عام حديث. تمرين مستقل: يشخص mismatch/expiry/unknown CA ويقترح إصلاحًا لا تعطيل الحماية؛ 80%.

### 4.9 — رحلة طلب وتشخيص طبقي

المتطلبات: `.a` من 4.1–4.8. النتيجة: يجمع الخريطة دون استبدال الدروس المالكة ويختار الفحص التالي من الدليل.

#### 4.9.a — مختبر التأسيس الجامع

التسلسل: DNS ← endpoint ← TCP/TLS عند وجودهما ← HTTP ← response ← timings. المختبر: خادم محلي محدود، `curl` و DevTools، عطل اسم وعطل منفذ وعطل route مُحاكاة منفصلة؛ المتوقع تمييز ثلاث طبقات فشل. تمرين مستقل: يشرح request/response ويعزل عطلًا جديدًا؛ 80% تغلق بوابة HTML التمهيدية فقط.

#### 4.9.b — Proxies والوقت والفشل الجزئي

المتطلبات: كل `.b` السابقة وتطبيق المرحلة 8. التعمق: proxy/CDN/LB ومسار upstream ← DNS/connect/TLS/TTFB timings ← budgets/timeouts ← MTU و HTTP/2/3 بربط لملاكها. الغلط: كل timeout من قاعدة البيانات أو كل 502 من client. مختبر: أدلة مجهزة لتأخير upstream وفشل TLS؛ المتوقع خطة تضييق سبب. تمرين مستقل: تقرير تشخيص بفرضيات وفحص ونتيجة وحدود اليقين؛ 80%.
